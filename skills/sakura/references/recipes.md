# Sakura cookbook

Generated by `cargo run -p agent_docs` from `compiler/examples/`. Edit the example files, then regenerate.

These eight projects teach supported Sakura APIs on the JavaScript backend. Each
project is exercised offline by `cargo test -p sakura_cli --test examples`;
HTTP and LLM exchanges are synthetic committed cassettes, with no network or API keys.
Use Node 26 for execution, including its built-in SQLite implementation.

The initial API baseline is compiler revision
[5cae349516c21714d90d36e87f1cfd6debe980c6](https://github.com/icantcodefyi/sakuralang/commit/5cae349516c21714d90d36e87f1cfd6debe980c6).
CI reruns these projects against the compiler in the same checkout. Build that
checkout's CLI and run `sakura --version` and `sakura prompt` before adapting a recipe;
pre-alpha APIs can change. An installed skill's frontmatter records its compiler
version and build revision. These teaching examples are separate from the agent
evaluation tasks.

The source of each page is its example's `recipe.md`, `sakura.toml`,
`src/main.sak` and fixture files. Run `cargo run -p agent_docs` from `compiler/`
to regenerate the cookbook and skill reference. Edit those sources, not the rendered pages.

## Decode JSON into a refined record

Decode an order once and let its field refinements reject invalid external data.

`Json.decode` infers `Order` from the return annotation and checks both the record
shape and the predicates on `item` and `quantity`. Its `Result` keeps malformed
JSON, missing fields and invalid quantities recoverable; `main` handles both
branches and reports the decoding path. Use `from` only for trusted values where a
failed predicate should be a defect. No permissions are needed.

The harness runs `main` (expecting `2 x tea`) and both tests. The tests cover a valid
record, invalid JSON, an empty name, missing quantity and both out-of-range bounds.

[Source project](https://github.com/icantcodefyi/sakuralang/tree/main/compiler/examples/json_refined) · harness mode: `run + test`.

```sakura test id=cookbook-json_refined project=json_refined
// milestone: M3
// mode: run
// spec: design §17.145

import std/json.{DecodeError}

type Quantity = Int where it >= 1 && it <= 100
type Order = { item: String where String.len(it) > 0, quantity: Quantity }

fn read_order(text: String) -> Result<Order, DecodeError> { Json.decode(text) }

pub fn main() -> Unit ! {Console} {
  match read_order("\{\"item\":\"tea\",\"quantity\":2\}") {
    Ok(order) => Console.print("{order.quantity} x {order.item}"),
    Err(err) => Console.print("invalid order at {err.path}: {err.message}"),
  }
}

test "JSON decoding validates the record fields" {
  expect_eq(
    read_order("\{\"item\":\"tea\",\"quantity\":2\}"),
    Ok(Order { item: "tea", quantity: 2 }),
  )
}

test "malformed JSON and invalid fields are recoverable" {
  expect(Result.is_err(read_order("not json")))
  expect(Result.is_err(read_order("\{\"item\":\"tea\",\"quantity\":0\}")))
  expect(Result.is_err(read_order("\{\"item\":\"tea\",\"quantity\":101\}")))
  expect(Result.is_err(read_order("\{\"item\":\"\",\"quantity\":1\}")))
  expect(Result.is_err(read_order("\{\"item\":\"tea\"\}")))
}
```

## Read a file from a CLI

Decode command-line flags into a record and count a selected file's bytes.

`Cli.parse` infers `Args` from the binding. `Path` validates the relative path;
`Fs.rooted(Dir.subdir(...))` narrows access to `data` before reading. The manifest
permits reads only below `./data`. Counting bytes avoids treating file contents as
trusted instructions or decoding them unnecessarily. This small recipe reads the
whole file; use `Fs.with_file` and bounded `Fs.read_chunk` for large inputs.

`CliError` and `FsError` propagate to the CLI's failure reporter. Tests replace
arguments and files with `Cli.of` and `Fs.memory`, checking success, missing flags
and a missing file. The harness also runs `sakura run -- --input note.txt` against
the committed data file and expects `4 bytes`.

```sakura test id=cookbook-cli_files project=cli_files
import std/cli.{Cli, CliError}
```

## Retry HTTP with an offline cassette

Retry a safe GET after a rate limit, with a finite attempt count and virtual time in tests.

`fetch` declares HTTP, clock and random effects. Its policy retries only
`RateLimited`, at most three attempts, with exponential backoff and a one-second
retry deadline. Jitter is disabled for this example. It uses the policy's delays;
it does not interpret `retry_after`. The deadline bounds retry scheduling, not the
duration of an individual request. `HttpError` propagates immediately. Other HTTP
statuses remain responses for the caller to inspect.

The cassette returns 429 then 200 for the identical request. `Http.recording` is
wrapped by `Http.scripted([])`, so an exchange cannot fall through to the network,
even in recording mode. `Clock.virtual` advances without sleeping. Tests check
success after 100 ms, exhaustion after 300 ms, and immediate transport failure.
The harness uses test mode; the manifest grants no network or environment access.

[Source project](https://github.com/icantcodefyi/sakuralang/tree/main/compiler/examples/http_retry) · harness mode: `test`.

```sakura test id=cookbook-http_retry project=http_retry
// milestone: M3
// mode: test
// spec: design §17.145

import std/duration.{Duration}
import std/fs.{Fs}
import std/http.{Any, Http, RateLimited}
import std/path.{Path}
import std/response.{HttpError, Response, Status}
import std/retry
import std/retry.{Policy}

fn fetch() -> Response ! {Clock, Http, Random, Fail<HttpError | RateLimited>} {
  let policy: Policy<HttpError | RateLimited> = Policy {
    ..retry.policy(
      fn(err: HttpError | RateLimited) {
        match err {
          RateLimited { .. } => true,
          HttpError { .. } => false,
        }
      },
      3,
    ),
    jitter: false,
    deadline: Some(Duration.seconds(1)),
  }
  retry.retry(policy, fn() { Http.get(url"https://recipes.invalid/status") })
}

test "429 then success replays with a virtual backoff" {
  with Fs.rooted(Test.fixtures()),
      Http.scripted([]),
      Http.recording(Path.of("status.jsonl")),
      Clock.virtual() {
    let response = fetch()
    expect_eq(response.status, Status.from(200))
    expect_eq(response.body, "ready")
    expect_eq(Clock.monotonic(), Duration.millis(100))
  }
}

test "three rejected attempts preserve RateLimited" {
  with Http.scripted([(Any, Response.status(429, "busy"))]), Clock.virtual() {
    expect_fails_with(fn() { fetch() }, fn(e) {
      match e {
        RateLimited { .. } => true,
        _ => false,
      }
    })
    expect_eq(Clock.monotonic(), Duration.millis(300))
  }
}

test "a missing exchange does not reach a host or retry" {
  with Http.scripted([]), Clock.virtual() {
    expect_fails_with(fn() { fetch() }, fn(e) {
      match e {
        HttpError { .. } => true,
        _ => false,
      }
    })
    expect_eq(Clock.monotonic(), Duration.millis(0))
  }
}
```

## Query SQLite with bound parameters

Keep SQL text literal and interpolate values as parameters, then decode typed rows.

`find_notes` returns `List<Note>`, which determines the row schema for `Sql.query`.
Each `sql"…"` interpolation becomes a bound parameter; neither string concatenation
nor a trust bypass is needed. `SqlError` propagates from the database operations.

Tests install `Sql.memory`, a real fresh in-memory SQLite database, so no filesystem
permission or persistent database is needed. One test proves SQL-looking input
matches only its literal value. Another runs a transaction that writes and then
fails on an absent table, checks `SqlError`, and proves the first write rolled back.
The harness uses test mode. For a persistent database, query `sakura doc std::sql::sqlite`
and supply an appropriately confined filesystem handler and manifest permissions.

```sakura test id=cookbook-sqlite_query project=sqlite_query
// milestone: M3
// mode: test
// spec: design §17.145

import std/sql.{Sql, SqlError}

type Note = { id: Int, title: String }

fn create_notes() -> Unit ! {Sql, Fail<SqlError>} {
  Sql.migrate([sql"create table notes (id integer primary key, title text not null)"])
}

fn add_note(title: String) -> Unit ! {Sql, Fail<SqlError>} {
  let _ = Sql.execute(sql"insert into notes (title) values ({title})")
}

fn find_notes(title: String) -> List<Note> ! {Sql, Fail<SqlError>} {
  Sql.query(sql"select id, title from notes where title = {title} order by id")
}

test "SQLite binds interpolated values, including SQL-looking text" {
  with Sql.memory() {
    create_notes()
    add_note("tea")
    let literal = "x' OR 1=1 --"
    expect_eq(find_notes(literal), [])
    add_note(literal)
    expect_eq(find_notes(literal), [Note { id: 2, title: literal }])
    expect_eq(find_notes("tea"), [Note { id: 1, title: "tea" }])
  }
}

test "a failing transaction rolls back earlier writes" {
  with Sql.memory() {
    create_notes()
    expect_fails_with(
      fn() {
        Sql.transaction(fn() {
          add_note("rolled back")
          let _ = Sql.execute(sql"insert into absent_table (title) values ({"bad"})")
        })
      },
      fn(e) {
        match e {
          SqlError { .. } => true,
        }
      },
    )
    expect_eq(find_notes("rolled back"), [])
  }
}
```

## Test a router endpoint directly

Call the router as a function to test dispatch, request validation and response handling.

`Request.json` validates a refined name and caps the body at 256 bytes. The handler
maps `BadRequest` to a generic 400 response. `Router.handle` dispatches by method
and path, producing 404 or 405 when appropriate. There is no listener, socket,
`Serve` handler or permission to configure.

The tests call the actual router, not just the endpoint function. They assert the
successful response body, rejection of malformed JSON, an invalid refinement and
an oversized body, plus missing-route and wrong-method statuses. The harness uses
test mode and never starts a server.

```sakura test id=cookbook-router_endpoint project=router_endpoint
// milestone: M3
// mode: test
// spec: design §17.145

import std/request.{BadRequest, Get, Request}
import std/response.{Response, Status}
import std/router.{Router}
import std/url.{Url}

type Greeting = { name: String where String.len(it) > 0 && String.len(it) <= 40 }

fn greet(req: Request) -> Response {
  try {
    let input: Greeting = Request.json(req, 256)
    Response.status(200, "Hello, {input.name}!")
  } catch {
    BadRequest { .. } => Response.status(400, "expected a short name"),
  }
}

fn app() -> Router<{}> { Router.new().post("/greet", greet) }

test "route dispatch calls the endpoint without a server" {
  let response = Router.handle(
    app(),
    Request.post("/greet", Json.encode(Greeting { name: "Mina" })),
  )
  expect_eq(response.status, Status.from(200))
  expect_eq(response.body, "Hello, Mina!")
}

test "malformed, invalid and oversized bodies return 400" {
  for body in ["not json", "\{\"name\":\"\"\}", String.repeat("x", 257)] {
    expect_eq(Router.handle(app(), Request.post("/greet", body)).status, Status.from(400))
  }
}

test "unknown paths and wrong methods are distinct" {
  expect_eq(Router.handle(app(), Request.post("/missing", "")).status, Status.from(404))
  expect_eq(Router.handle(app(), Request.of(Get, Url.from("/greet"))).status, Status.from(405))
}
```

## Exercise an LLM tool with a script

Drive a tool call and final answer with scripted model output, then replay the same provider exchange.

`@tool` gives `Tool.of(platform)` its name, description and argument schema. The
agent validates model arguments and invokes the real function under the caller's
handlers. The model receives no additional authority. `UnknownStation` becomes a
`ToolError` and stops the loop; the test checks its tag and verifies no success log
was produced. Other `LlmError` and `ToolError` variants remain in the signature.

`Llm.scripted` consumes responses in order. The successful test asserts both the
answer and the tool's captured output, so returning a canned answer without calling
the tool does not pass. A synthetic two-turn cassette exercises the provider shape
through `Llm.replay`, which denies network fallback. The harness uses test mode.
The manifest grants no network or key access. Budgets are intentionally unlimited
here; the budgeted-agent recipe exercises finite accounting.

```sakura test id=cookbook-scripted_tool project=scripted_tool
import std/agent.{Agent}
import std/budget.{Budget}
import std/fs.{Fs}
import std/llm.{Llm, LlmError, Request}
import std/path.{Path}
import std/prompt.{Prompt}

error UnknownStation

@tool("Look up a station platform")
fn platform(station: String) -> Int ! {Console, Fail<UnknownStation>} {
  if station != "North" { fail UnknownStation }
  Console.print("looked up {station}")
  4
}

  Agent.run(Agent { request, tools: [Tool.of(platform)], max_steps: 3, stop: fn(_) { false } })
}

test "scripted model calls the actual tool before answering" {
  with Budget.unlimited(),
      Llm.scripted([
        "\{\"tool_use\":[\{\"name\":\"platform\",\"input\":\{\"station\":\"North\"\}\}]\}",
        "4",
      ]) {
    expect_eq(platform_answer(), 4)
    expect_output(["looked up North"])
  }
}

test "tool errors end the loop before an answer" {
  with Budget.unlimited(),
      Llm.scripted([
        "\{\"tool_use\":[\{\"name\":\"platform\",\"input\":\{\"station\":\"Unknown\"\}\}]\}",

    expect_fails_with(fn() { platform_answer() }, fn(e) {
      match e {
        ToolError { tag, .. } => tag == "UnknownStation",
        _ => false,
```

## Bound an agent loop and its budget

Set both a turn limit and a spending limit, and test rejection before an unaffordable call.

`Agent.run` permits at most `max_steps` model turns and offers no tools on the last
turn. The tests verify that a model still requesting a tool then fails with
`InvalidOutput`. `BudgetExceeded`, other `LlmError` variants and `ToolError` propagate
in the declared failure union.

For finite accounting, put `Budget.limits` outside `Llm.anthropic` and replay HTTP
under `Http.recording` with an empty scripted fallback. Do not substitute
`Llm.replay` or `Llm.recording` here: those helpers install `Budget.unlimited`
internally. The placeholder `Secret` is not an API key, and no host HTTP handler or
network permission is installed.

The cassette's two turns report synthetic usage of 140 tokens each. The provider
reserves an estimate and settles that usage; the agent also holds a temporary
one-call reservation while a turn is in progress. Consequently the two-call run
needs a call limit of three for its overlapping reservations. A limit of two
rejects the second provider call. The tests exercise both cases, a token limit that
rejects before any scripted response is consumed, and the final-turn rule. These
are local accounting tests, not measured provider prices or a hard billing guarantee.
The harness uses test mode; no key, paid call or live service is involved.

```sakura test id=cookbook-budgeted_agent project=budgeted_agent
// milestone: M3
// mode: test
// spec: design §17.145

import std/agent.{Agent}
import std/budget.{Budget, BudgetExceeded, Calls, Limits, Tokens}
import std/fs.{Fs}
import std/http.{Http}
import std/llm.{InvalidOutput, Llm, LlmError, Model, Request}
import std/path.{Path}
import std/prompt.{Prompt}
import std/tool.{Tool, ToolError}

@tool("Count waiting tasks")
fn waiting() -> Int { 2 }

fn count_tasks(max_steps: Int) -> Int
  ! {Budget, Llm, Fail<LlmError | ToolError>}
  requires max_steps > 0
{
  let request: Request<Int> = Llm.request("Use the waiting tool.", Prompt.text("How many tasks?"))
  Agent.run(Agent { request, tools: [Tool.of(waiting)], max_steps, stop: fn(_) { false } })
}
```

## Update list indices with List.set

Reassign the new list returned by `List.set` while preserving earlier versions.

Collections have value semantics. `List.set(values, index, value)` returns a new
list; ignoring the result leaves `values` unchanged. The loop computes the length
once, handles empty input, then uses the half-open range `0..n`. Every read and
write is in bounds because replacement preserves length. An external index needs
both the nonnegative and upper-bound checks, as `replace_if_present` demonstrates.

The tests check changed values, the unchanged original list, empty and singleton
inputs, and external indices below zero, at the length and inside the list.
The harness also runs `main` and checks `[3, 0, 7, 0]`. No effects other than its
console output, permissions or slice/concat reconstruction are needed.

[Source project](https://github.com/icantcodefyi/sakuralang/tree/main/compiler/examples/indexed_update) · harness mode: `run + test`.

From the repository root, with this checkout's `sakura` on `PATH`:

```sh
cd compiler/examples/indexed_update
sakura check --json
sakura run
sakura test --json
```

```sakura test id=cookbook-indexed_update project=indexed_update
// milestone: M3
// mode: run
// spec: design §17.145

fn replace_negatives(values: List<Int>) -> List<Int> {
  var updated = values
  let n = List.len(updated)
  if n == 0 { return updated }
  for i in 0..n {
    let value = List.get(updated, i).expect("i is inside the half-open range")
    if value < 0 { updated = List.set(updated, i, 0) }
  }
  updated
}

pub fn main() -> Unit ! {Console} { Console.print("{replace_negatives([3, -2, 7, -1])}") }

test "updates preserve earlier versions" {
  let original = [3, -2, 7, -1]
  expect_eq(replace_negatives(original), [3, 0, 7, 0])
  expect_eq(original, [3, -2, 7, -1])
}

test "empty, singleton and unchanged inputs" {
  expect_eq(replace_negatives([]), [])
  expect_eq(replace_negatives([-1]), [0])
  expect_eq(replace_negatives([0, 4]), [0, 4])
}

fn replace_if_present(values: List<Int>, index: Int, value: Int) -> List<Int> {
  if index >= 0 && index < List.len(values) { List.set(values, index, value) } else { values }
}

test "external indices are checked before replacement" {
  expect_eq(replace_if_present([7], -1, 9), [7])
  expect_eq(replace_if_present([7], 1, 9), [7])
  expect_eq(replace_if_present([], 0, 9), [])
  expect_eq(replace_if_present([7], 0, 9), [9])
}
```
