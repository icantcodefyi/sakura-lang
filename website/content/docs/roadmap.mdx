This page says what you can use today, what is still coming before 1.0, and what is planned
after 1.0. Read it before you pick Sakura Lang for a project. No release has a date.

<Callout type="info" title="Latest release">
  **Latest release: `v1.0.0-beta.4` (2026-10-22).** A beta is a preview of 1.0: it may have bugs
  and may still change before 1.0.0, so it is not for production. See [what changed](/docs/changes)
  and [what you can rely on](/docs/stability).
</Callout>

## What works today

Everything in this section ships in the latest beta.

- **The language.** Types, effects (a function's type lists what it may do, such as read
  files or call the network), handlers that supply those effects, pattern matching, typed
  errors, and contracts: `requires` and `ensures` checks on functions, plus refined types such
  as `Int where it >= 0`.
- **Two backends.** A backend is what the compiler turns your program into. JavaScript is the
  default. WebAssembly (`--target wasm`) runs every program the same way, with Node as the
  host. CI compares the two on Linux x64 and ARM64, Apple silicon and Intel macOS, and
  Windows x64.
- **Contract proofs.** [`sakura verify`](/docs/agents/verify) tries to prove your contracts
  with the Z3 solver, which you install yourself (it is never downloaded for you). A build
  drops a runtime check only when a matching proof covers it; every other check stays.
- **A standard library.** JSON, SQLite, files, HTTP clients and servers, command-line
  parsing, structured concurrency, model (LLM) calls, tools and agent loops, plus the web
  platform's byte, text, URL, header, form, crypto, stream, compression and WebSocket APIs.
  See the [standard library](/docs/stdlib).
- **Permissions.** `sakura run` checks the files, hosts and environment variables your
  program declares in [`sakura.toml`](/docs/manifest) and exits with status 75 when one is
  missing. This is not an operating-system sandbox for arbitrary JavaScript or trusted
  foreign code.
- **Tools for coding agents.** A language server, an [MCP server](/docs/agents/mcp), a
  downloadable skill, [typed holes](/docs/agents/typed-holes) (gaps in your code that the compiler describes), the
  [trust audit](/docs/agents/audit), [offline API search](/docs/agents/doc),
  [build manifests](/docs/agents/build-manifest), [recorded test cassettes](/docs/agents/cassettes)
  and generated contract tests (`sakura test --contracts`).
- **Install channels.** npm, Homebrew, release archives and an installer script, for macOS
  (Apple silicon and Intel), Linux (x64 and ARM64) and Windows x64. See [Install](/docs/install).

### Experimental today [#m5-native-code-experimental]

Experimental features are opt-in and may change or go away in any release, without a migration.

- **Native executables** (`--target native`). The macOS arm64, Linux x64 and Linux arm64
  release binaries include it, and you need a system C compiler (`cc`) to link. It runs every
  standard service; `WebSocket` from the release after `v1.0.0-beta.5`. No native performance claim is made yet. See
  [Native code](/docs/native).
- **Workers** (`std/worker`): a second copy of your program running in parallel, with its own
  memory. See [Workers](/docs/tour/concurrency#workers-experimental).

### Not available today

- PostgreSQL (`Sql.postgres`) is not implemented and has no release planned. Use SQLite.
- Packages: a `[dependencies]` table in `sakura.toml` is refused.
- A browser host: the WebAssembly backend runs under Node.

## What comes next: 1.0.0

1.0.0 is the first production release. It adds no big features over the betas; it is the
same language with evidence that it holds up. Before 1.0.0 is tagged:

- **Fuzz testing.** Every fuzz target (a test that feeds the compiler random inputs) runs
  at least 24 CPU-hours with no soundness bug, meaning no case where a program is accepted
  but behaves wrongly.
- **Real programs upgraded.** Sample programs written on earlier releases are upgraded through
  each beta, following only the published migration notes.
- **Agent results.** Measured results from coding agents writing Sakura Lang.
- **A complete specification** of the language.
- **Signed macOS downloads.**
- **A quiet last beta.** No serious bug and no contract change after the last beta. A
  contract change means another beta first.

Until 1.0.0, a beta may still change behaviour, and each breaking change is listed in the
[changelog](/changelog) with a migration. From 1.0.0 your source code keeps working within
the 1.x line; see [Stability](/docs/stability).

## After 1.0

- **Packages**, added in a 1.x release without breaking existing projects.
- **Native executables as a stable target.** Native stays experimental until it meets its
  stabilization conditions in a 1.x release.
- **Faster native code**, from optimizations that are not built yet.
- **Publishing the compiler on crates.io**, an online playground and GitHub syntax
  highlighting (Linguist).

## Release history

| Release | What it brought | Published |
| --- | --- | --- |
| `v1.0.0-beta.4` | Experimental native executables in the release binaries; `W8001` warns when a list or map update copies; memory reuse on WebAssembly and native | 2026-10-22 |
| `v1.0.0-beta.3` | Node programs can call a Sakura library; faster `sakura verify` | 2026-10-21 |
| `v1.0.0-beta.2` | Experimental workers; refined types in JSON Schema | 2026-10-21 |
| `v1.0.0-beta.1` | The first 1.0 beta: binary HTTP bodies, streams, URL patterns, WebSockets, timers; the first stability rules | 2026-10-21 |
| `v0.1.0` | The WebAssembly backend complete; web byte, URL, header, form and crypto APIs; Linux ARM64, Windows and Intel Mac | 2026-10-20 |
| `v0.1.0-alpha.1` | The first public preview: the language, standard library, editor and agent tools | 2026-10-18 |

[Changes since 0.1.0](/docs/changes) explains each beta in more detail.

## For contributors

Internally the work is split into milestones: M3 (the JavaScript language and agent tools)
and M4 (WebAssembly and contract proofs) are complete, and M5 (native code) is in progress.
The [road to 1.0](https://github.com/icantcodefyi/sakuralang/blob/main/docs/plans/road-to-1.0.md)
sets the release order, the [M3 gate report](https://github.com/icantcodefyi/sakuralang/blob/main/docs/plans/m3-gate-report.md)
and [M4 plan](https://github.com/icantcodefyi/sakuralang/blob/main/docs/plans/m3-completion-and-m4.md)
record the finished milestones, the [native plan](https://github.com/icantcodefyi/sakuralang/blob/main/docs/plans/m5-native.md)
tracks M5, and [the design notes](https://github.com/icantcodefyi/sakuralang/blob/main/docs/design.md)
record each decision.
