<Callout type="info" title="Where things stand">
  Sakura Lang is pre-alpha and builds from source. The core language and M3 functionality run on JavaScript. **M3 is complete:** gates 1–9 and 11 pass at `a843e60` and gate 10, the security review, was signed on 2026-10-18 under the owner's delegation (see the gate report below). `sakura build`, `run` and `test` support `--target wasm`, and `sakura verify` checks contracts with a separately installed solver. There are no milestone dates or published releases.
</Callout>

The sequence is **M3 → M4 → M5**. The [completion plan](https://github.com/icantcodefyi/sakuralang/blob/master/docs/plans/m3-completion-and-m4.md) defines the gates; [design §17.81–§17.99](https://github.com/icantcodefyi/sakuralang/blob/master/docs/design.md) defines the provisional M4 decisions. M0–M2 provide the existing parser, type/effect checker, JS backend, handlers, typed holes, formatter and test runner.

## M3: finish the JS language and agent tooling

Working today:

- Runtime contracts and refinements, bounded compile-time literal evaluation (`V5004`, with `V5002` retired), refined-target `Untrusted.validate` (`V5003`) and collection-only `W5005`; opaque constructors and fields rejected outside their module with `V1006`; compiler-known prelude `Trust`, with `@trust("reason")` restricted to trusted sink arguments (`V6001`).
- Scoped capability/resource escape checks (`V6002`/`V6003`) and `V6001` for user externals receiving or constructing another package's capabilities or any handler.
- Std data, JSON schemas and codecs, SQLite and memory SQL, filesystem and file callbacks, HTTP, serving, CLI, structured tasks, budgets, tools and agent loops. `sql"…"` arguments use `SqlValue.from` conversions and become bound parameters.
- `Tool.of` on a named `@tool` function, `@llm` body generation, and effect-row parameters on types: `Tool<e>`, `Agent<T, e>`, `Router<e>`.
- `sakura new <cli|lib|agent|api> <name>`, `init`, LSP, compiler MCP, impact-aware fixes and frozen-spec checks. Analysis reuses unchanged modules' signatures and bodies; a private-body edit parses, lowers and checks only its module. Item collection, imports and exports remain global. Bodies reachable from a refinement predicate are part of the interface hash, so editing one invalidates reuse.
- [`sakura audit`](/docs/agents/audit), [`sakura doc`](/docs/agents/doc), [`sakura build --manifest`](/docs/agents/build-manifest), [`sakura test --record`](/docs/agents/cassettes) and `sakura test --contracts` (a generated property per contracted `pub fn`, `W7001` when it gives up).
- `Html.from` and nested `Html` templates; `Untrusted<T>` in `sql"…"` is a bound parameter, in `html"…"` escaped text and in `url"…"` a percent-encoded `UrlPart` (design §17.101, §17.124). `Http.recording`, `Llm.replay`, `Llm.recording` and `Test.fixtures` for offline cassettes, and streaming HTTP (`Http.stream`, `Http.read_chunk`).
- `sakura run` checks declared root permissions (exit 75 on denial) and passes `[permissions]` as `SAKURA_PERMISSIONS`; host handlers enforce filesystem, network and environment grants. This is not an OS sandbox for arbitrary JS or trusted FFI.
- Tests accept escaping typed failures and report them as failed tests. `Llm.anthropic` requests SSE and delivers one partial callback per text delta; local mock tests cover this, not a live-provider guarantee.

All twelve repository examples pass their current harness modes: seven run plus test (`hello`, `contracts`, `counter`, `typed_errors`, `word_count`, `graph`, `secrets`) and five test (`json_api`, `llm_extract`, `property`, `concurrency`, `agent_loop`). None is check-only. `llm_extract`, `agent_loop` and `secrets` replay committed **synthetic** cassettes with the test network denied. Their fixture READMEs describe provenance; this is not live-provider validation.

## M4: WASM and contract verification

Working today (source builds; no stable release):

- **WASM (W1/W2):** [`build`, `run` and `test --target wasm`](/docs/tour/memory#backends), with Node as the host. The [runtime ABI](https://github.com/icantcodefyi/sakuralang/blob/master/compiler/runtime/rt/ABI.md) defines bounded linear memory, conservative reference counting, persistent collections, frames, the trampoline and scheduler. LIR lowering makes continuations, closure environments, boxing and balanced `Dup`/`Drop` explicit; `sakura build --emit lir` writes it as text. The [ABI research](https://github.com/icantcodefyi/sakuralang/blob/master/research/09-m4-abi-and-encoding.md) records the design rationale.
- **Host operations:** HTTP sends and streams, SQLite, `Llm.stream`, `Serve.host()` and `Log.json()` run on WASM. **HTTP requests carrying `Secret` headers are still refused** until the approved transport change (security review W0, plan WS12 item 7) lands; this includes bearer-authenticated `Llm.anthropic` over `Http.host()`. Scripted and replayed streams work without that transport. This is not live-provider validation.
- **Parity:** CI requires the JS/WASM matrix on Ubuntu and macOS through `ci-required`. The harness compares the run/test semantics corpus and example runs for output, exits, defects and effect traces, including task numbers. Backend-specific expectations preserve the intentional JS safe-integer / WASM i64 differences. It also reports host-import coverage; local-server tests exercise network and serving operations outside the offline corpus.
- **Verification:** [`sakura verify`](/docs/agents/verify) runs pinned Z3 workers over Core obligations and reports `proved`, `disproved`, `unknown` or `unsupported`. cvc5 cross-checks `unsat` when installed. JS builds remove only eligible checks covered by matching authenticated proofs; other checks remain. Body edits invalidate the function's own proofs. See the [verification tour](/docs/tour/verification).
- **JS performance:** direct calls, bound handler dispatch, interval-proved arithmetic, owned updates and total-predicate `D011` bracket elision have landed in the WS-P work. `sakura build --dump direct`, `--dump core` and `--dump owned` expose compiler facts; the internal `--no-direct` switch exercises the CPS path. These optimizations do not establish the full performance acceptance bar or a WASM speedup.

Still planned: resumable JS loops, LIR direct-region optimization, niche layout (`--emit lir --layout niche` is refused; WASM emission always uses tagged layout), removal of proved predicates' computation, the full WASM performance envelope, cached-verdict reuse in `verify`, and i64 counterexample replay. Tagged layout is the implemented baseline. Wasmtime remains an additional gate for pure and fake-handler programs; the CLI runs WASM through Node. The [completion plan](https://github.com/icantcodefyi/sakuralang/blob/master/docs/plans/m3-completion-and-m4.md#37-after-the-in-flight-work-round-9-17139) tracks these separately from W1/W2 parity.

### Agent development tools (DX0–DX7)

The compiler reports its capabilities through MCP. A downloadable skill, `sakura setup`, generated diagnostic references and eight offline cookbook projects are available. The first owner-approved agent-evaluation pilot ran 48 episodes for $4.20; its [report](https://github.com/icantcodefyi/sakuralang/blob/master/evals/agent-dx/reports/2026-10-18-pilot.md) records small-sample results and input-cap limits. Further evaluation and publication remain owner-controlled; release tooling is prepared. The VS Code client can be packaged locally and is not published. DX8 plugin packaging, the playground and Linguist submission remain planned; see the [agent DX plan](https://github.com/icantcodefyi/sakuralang/blob/master/docs/plans/agent-dx.md).

For `scale(p, total) = total * p / 100`, proving `ensures result <= total` on normal return does not prove the multiplication cannot overflow. Overflow is a separate obligation. The wrong `/ 50` body has the counterexample `p = 100, total = 1`.

M4 excludes WasmGC, JSPI, typed continuations, WASI components, browser std support, threads, Perceus reuse/borrow inference, loop/recursion proofs, Float/String solver theories and proof certificates.

## M5: native code and Perceus

Planned: a Cranelift backend adds native execution, borrow inference and reference-counted in-place reuse, `W8001` copy diagnostics, and internal region optimizations. Acceptance requires that live aliases preserve values, dead aliases allow reuse, cancellation and handler state pass sanitizer checks, and JS, WASM and native agree on the applicable corpus. No native performance claim is established yet.

## Decisions still open

Plan §6 retains questions about package-management placement, real-provider recording ownership and Windows coverage. The solver decision is now recorded in §3.5: a pinned external binary on `PATH` or `--solver`, without automatic downloads (V2 pins Z3 5.3.1 and cvc5 1.4.2). The std index records PostgreSQL as deferred past M4; SQLite is implemented and `Sql.postgres` is absent. These are scope decisions, not release dates.
