Agents read Markdown more reliably than rendered HTML. This site serves every page in a form that is easy to fetch and cheap to put in a context window.

## Endpoints

| URL | Contents |
| --- | --- |
| [`/llms.txt`](/llms.txt) | An index of every docs page with its title, description, and URL, following the [llms.txt](https://llmstxt.org) convention. |
| [`/llms-full.txt`](/llms-full.txt) | Every docs page concatenated into one Markdown file. |
| `/docs.md` | The docs root (this site's introduction) as Markdown. |
| `/docs/<path>.md` | Any docs page as Markdown. Append `.md` to its URL. |

Examples:

```bash
curl https://<this-site>/llms.txt
curl https://<this-site>/llms-full.txt
curl https://<this-site>/docs.md
curl https://<this-site>/docs/tour/effects.md
```

Diagnostics link to these Markdown URLs directly. The `docs` field of an `E0402` diagnostic is `/docs/tour/effects.md#undeclared-effects`, which points at the [Undeclared effects](/docs/tour/effects#undeclared-effects) section.

Every rendered page also has a **Copy as Markdown** button and a link to its `.md` version.

## What to fetch

**Fetch `/llms-full.txt` once at the start of a session.** The language tour, the agent docs, and the standard library overview together are the whole language as currently designed. Loading all of it avoids guessing at syntax, and guessing is a common source of invalid code when a model works in an unfamiliar language.

Use per-page `.md` URLs when you need to refresh one topic or follow a link from a diagnostic.

Use `/llms.txt` when context is tight and you want to choose which pages to load.

## The size budget

Vow's grammar is deliberately small: 26 keywords, one way to bind, one way to branch, one way to fail. A design goal is that a complete language reference, enough to write correct Vow without other sources, fits in a few thousand tokens. When the reference exists, it will be served from this site alongside the docs.

## System prompt snippet

A starting point for an agent that writes Vow:

```md
You write code in Vow, an agent-first language. Before writing code, load
https://<this-site>/llms-full.txt and follow it exactly. Do not borrow syntax
from other languages.

Rules:
- Write signatures first: parameter types, return type, effect row after `!`,
  and `requires`/`ensures` contracts. Leave bodies as `todo()` and run
  `vow check --format json`.
- Every effect and error goes in the signature. There are no exceptions, no
  null, no `mut`, no `async`/`await`, no `try`/`catch`, no `?` operator.
- Fail with `fail X` and declare `Fail<E>`. Absence is `Option<T>`.
- Validate outside data with `.validate(Type)`. Never use `.trust_because`
  without a specific, true reason.
- Apply fixes with "safety": "safe" automatically. Apply "changes-behaviour"
  fixes only when they match the task. Never apply "changes-signature" fixes
  silently: list every signature change in your summary for human review.
- When a diagnostic has a "docs" URL, fetch it before guessing.
```
