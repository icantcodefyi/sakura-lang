  The compiler is under construction (milestone M0) and nothing runs yet. The Markdown docs exports and the repository's
  `docs/llms.txt` exist today. The `vow` CLI, JSON diagnostics, typed holes, and the MCP server are designed for v0 but
  not implemented.

Vow is designed to be written by agents and reviewed by humans. The signature is the contract: parameter types with refinements, result type, effect row, error union, and `requires`/`ensures`. Agents write bodies against it; humans review signatures and the diff of signatures.

## Available today

| Resource | What it is |
| --- | --- |
| [`/llms.txt`](/llms.txt) | Index of every page on this site, with titles, descriptions, and URLs. |
| [`/llms-full.txt`](/llms-full.txt) | Every page on this site concatenated into one Markdown file. |
| `/docs/<page>.md` | Any page on this site as Markdown. Append `.md` to its URL; the docs root is `/docs.md`. |
| Copy as Markdown | A button at the top of every page, next to a menu with the `.md` link and the GitHub source. |
| [`docs/llms.txt`](https://github.com/icantcodefyi/vow/blob/master/docs/llms.txt) | The language reference for agents: the whole core language in one file of about 3,000 tokens. Lives in the repository. |
| [`docs/design.md`](https://github.com/icantcodefyi/vow/blob/master/docs/design.md) | The authoritative v0 design. When anything else disagrees with it, it wins. |

The two `llms.txt` files are different things. See [llms.txt](/docs/agents/llms-txt).

## Planned

| Tool | Purpose | Design |
| --- | --- | --- |
| `vow check --json` | Diagnostics, holes, and obligations as JSON Lines. | design §12.2, M0 |
| `?name` typed holes | Placeholders the checker reports with expected type, effects, locals, and candidates. | design §12.4, M2 |
| `vow prompt` | Emits `docs/llms.txt` matched to the compiler's edition, plus requested library signatures. | design §12.1, M2 |
| `vow fix`, `--frozen-specs` | Applies compiler fixes by impact class and rejects patches that touch frozen specs. | design §7.3, M3 |
| `vow mcp serve` | The compiler as Model Context Protocol tools. | design §12.6, M3 |

Milestones are defined in [design §14.3](https://github.com/icantcodefyi/vow/blob/master/docs/design.md). See also the [roadmap](/docs/roadmap).

## The intended loop

This is how an agent is expected to work once the toolchain exists. None of these commands run yet.

<Steps>
<Step>

### Load the language

Read `docs/llms.txt` once per session (later: the output of `vow prompt`). It is the entire core language. Look up library signatures with `vow doc --search` or the MCP `symbol_query` tool instead of guessing.

</Step>
<Step>

### Write signatures first, bodies as holes

```vow
fn clamp(x: Int, lo: Int, hi: Int) -> Int
  requires ordered: lo <= hi
  ensures bounded: lo <= result && result <= hi
{
  ?body
}
```

`vow check` accepts holes. Signatures are what a human reviews, so get them right first.

</Step>
<Step>

### Check

Run `vow check --json`, or call the MCP `check` tool. Each [typed hole](/docs/agents/typed-holes) comes back as a `hole` record with its expected type, allowed effects, locals, and ranked candidates.

</Step>
<Step>

### Fill holes and fix diagnostics

Each problem is a `diagnostic` record with a stable code, byte spans, structured expected/actual, and fixes. See [Diagnostics](/docs/agents/diagnostics). `vow explain V3001` gives the rationale for a code.

</Step>
<Step>

### Apply fixes by impact class

`local` fixes that are `machine_applicable` are safe to apply. `interface_change`, `contract_change`, and `authority_change` fixes are never `machine_applicable`; `vow fix` never applies the last two. Run `vow test --json`, then `vow fmt`.

</Step>
<Step>

### Report signature changes

If the task really needs a new effect, error tag, permission, or a changed contract, make the change and list it for the reviewer. During repair, specs can be frozen (`--frozen-specs`), and any patch that touches them is rejected with `V8020`.

</Step>
</Steps>

## What an agent should never do

- Add an effect, error tag, or `[permissions]` entry without flagging it.
- Weaken or delete a `requires`, `ensures`, or `where` clause, or edit a `test` body, to make a check pass. Contract violations (`D020`, `D021`) mean the caller or callee is wrong, not the spec.
- Use `.trust(@trust("..."))`, `Secret.expose`, `.expect`, or `Email.from` outside trusted boundaries, or without a true reason.
- Leave a `?hole` in code meant to build. `vow build` and `vow run` reject it with `V2050`.
