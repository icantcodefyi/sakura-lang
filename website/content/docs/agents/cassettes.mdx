Ordinary `sakura test` denies network access. `Http.recording` and `Llm.replay` let tests exercise provider-shaped exchanges offline using JSON Lines cassettes under `tests/fixtures/`.

## HTTP replay

`Test.fixtures()` returns a `Dir` rooted at the package's `tests/fixtures` directory. It is read-only during ordinary tests. Install it with `Fs.rooted`, then put `Http.recording` inside an outer HTTP handler. The first handler in a `with` list is outermost.

This test belongs in the repository's `compiler/examples/secrets` package, alongside its committed `billing.jsonl` fixture:

```sakura
import std/decimal.{Decimal}
import std/fs.{Fs}
import std/http.{Http}
import std/path.{Path}
import std/request.{Request}
import std/url.{Url}

test "billing cassette replays offline" {
  with Fs.rooted(Test.fixtures()), Http.scripted([]),
      Http.recording(Path.of("billing.jsonl")) {
    let amount = Decimal.parse("12.34").unwrap_or(Decimal.zero())
    let req = Request.post_json(Url.from("https://billing/charge"), amount)
    expect_eq(Http.send(req).status, 200)
  }
}
```

A request matches on method, URL, ordinary headers and body. `Request.secret_headers` are neither recorded nor matched. Keep credentials in that secret channel; ordinary headers and bodies are cassette data. Identical requests consume matching responses in order; the last response repeats. Without recording mode, a miss fails with `HttpError` and a message pointing to `sakura test --record`.

## Cassette format and redaction

A cassette is a JSON Lines file (design §17.122). Three rules apply:

1. **Header line.** The first line is `{"schema_version":"1.0","kind":"cassette"}`; each later line is one exchange, `{method, url, headers, body, status, response_headers, response_body}` (`body_base64` and `response_body_base64` for bytes that are not UTF-8). A missing or empty file has no exchanges and gets the header on its first append. A file whose first non-empty line has no `schema_version`, or a major version other than `1`, fails to open with `HttpError` naming the file and `sakura test --record`.
2. **Credential headers are refused.** A request whose ordinary `headers` contain `authorization`, `proxy-authorization`, `x-api-key`, `api-key`, `x-auth-token` or `cookie` (in any case) fails under `Http.recording` with `HttpError` reading `header <name> belongs in secret_headers (Http.bearer); not recorded`. This happens before any replay or forward, recording or not, so a plain-string token is never written. Use `Http.bearer` or another `secret_headers` entry instead.
3. **`set-cookie` is redacted.** A `set-cookie` response header is stored as `["set-cookie", "<redacted>"]` and replays as that literal. Other response headers are stored as the server sent them.

The URL and the request body are stored verbatim: a replay must match them. A body that is not UTF-8 (an image upload, a compressed answer) is stored as Base64 in `body_base64` or `response_body_base64` instead, and a `Text` and a `Bytes` request body with the same bytes match the same exchange. A replayed response body is `Bytes`, as `Http.host()` delivers it, so read it with `Response.text`, `Response.json` or `Response.bytes`. Each redirect hop is its own exchange: `Http.recording` follows a recorded 3xx like the host does, and a cassette without 3xx exchanges replays unchanged. A `Secret` cannot reach them without an audited `Secret.expose` (`V2031` in `url"…"`, `V2032` in `Json.encode`), but a credential that was never a `Secret` and is put in a query string or body is outside this guarantee.

## LLM replay

`Llm.replay(path)` installs the Anthropic adapter over `Http.recording`, an empty scripted outer HTTP handler and `Budget.unlimited()`, using a placeholder secret. It needs `Fs`, not live provider credentials. It replays generation, free text, partial callbacks and tool turns; missing exchanges fail as `ProviderError`.

The [LLM extraction recipe](/docs/cookbook/llm_extract) uses `Fs.rooted(Test.fixtures())`, an outer `Budget.unlimited()` for its generated `@llm` function, and `Llm.replay(Path.of("extract_ticket.jsonl"))`. The [agent-loop recipe](/docs/cookbook/agent_loop) also scripts its knowledge-base tool.

`Llm.replay` and `Llm.recording` keep one cassette open per handler installation. Repeated identical requests consume matching responses in recorded order, then repeat the last response.

From the repository root, after building the CLI:

```sh
cd compiler/examples/llm_extract
../../target/debug/sakura check
../../target/debug/sakura test
```

## Recording is opt-in

`--record` is present in `sakura test --help`. It sets recording mode, makes the fixture directory writable and grants only the manifest's network hosts. With no `net` entries it refuses to start (exit 75). Run from the prepared project directory:

```sh
sakura test --record
```

A cassette miss can then forward through the outer `Http` handler and append the response. Existing hits still replay.

For provider recording, install `Llm.recording(path, Llm.anthropic(key, model))` inside an outer `Http` and `Fs` handler. It replays cassette hits and records misses through the supplied provider under `--record`; a miss without recording mode fails as `ProviderError`. Use `Http.host()` and a real secret key for live calls. `Llm.replay` keeps its empty scripted outer handler even with `--record`, so it cannot fetch a missing provider exchange itself. Review cassette diffs before committing them. The examples below were executed with synthetic responses, without a live provider or real credentials.

`Llm.anthropic` always sends to `https://api.anthropic.com`, so a cassette's request keys are the same on every machine. To point the adapter at another endpoint, such as a local proxy, pass it as a value with `Llm.anthropic_at(base, key, model)`, which sends to `<base>/v1/messages`; the manifest's `net` list applies to `base` like any request. No process variable is read: `ANTHROPIC_BASE_URL` is ignored since `v1.0.0-beta.1`. A program that takes the endpoint from its environment reads it under its own `Env` handler and passes it:

```sakura
import std/budget.{Budget}
import std/http.{Http}
import std/llm.{Llm, Model}
import std/url.{Url}

/// The adapter for the endpoint the environment names, else Anthropic's API.
fn provider(key: Secret<String>, model: Model) -> Handler<Llm, {Budget, Http}> ! {Env} {
  let base = Option.unwrap_or(Env.get("ANTHROPIC_BASE_URL"), "https://api.anthropic.com")
  Llm.anthropic_at(Url.from(base), key, model)
}
```

Each call reserves `ceil(bytes of the request body / 4) + max_tokens` tokens at the model's price against the installed `Budget` before it is sent, then settles the usage the response reports. A `Budget` handler that logs each reservation and forwards to the one outside it shows what a test spends:

```sakura
import std/budget.{Budget}

/// Prints each reservation, then forwards it to the `Budget` outside.
fn logged() -> Handler<Budget, {Budget, Console}> {
  handler Budget {
    fn reserve(c) { Console.print("reserve {c.tokens} tokens"); Budget.reserve(c) }
    fn settle(r, actual) { Budget.settle(r, actual) }
  }
}
```

### A synthetic record-then-replay example

In a scratch package, set `[permissions]` in `sakura.toml` to include `net = ["api.anthropic.com:443"]`, then put this in `src/main.sak`. The outer HTTP handler supplies an invented response; it makes no network request:

```sakura
import std/fs.{Fs}
import std/http.{Http, Matcher}
import std/llm.{Llm, Model, Request}
import std/path.{Path}
import std/prompt.{Prompt}
import std/response.{Response}

test "record a synthetic model response and replay it offline" {
  let response = Response.status(200,
    "\{\"content\":[\{\"type\":\"text\",\"text\":\"hello\"\}],\"stop_reason\":\"end_turn\",\"usage\":\{\"input_tokens\":1,\"output_tokens\":1\}\}")
  with Http.scripted([(Matcher.Any, response)]), Fs.rooted(Test.fixtures()),
      Llm.recording(Path.of("hello.jsonl"),
        Llm.anthropic(Secret.of("synthetic-key"), Model.of("demo-model"))) {
    let req: Request<String> = Llm.request("Be brief.", Prompt.text("Say hello."))
    expect_eq(Untrusted.check(Llm.generate_text(req), "greeting", fn(s) { s == "hello" }), Ok("hello"))
  }
}
```

Run `sakura test --record` once to create `tests/fixtures/hello.jsonl`, then `sakura test` to replay it offline. Replacing the outer handler with `Http.scripted([])` still passes after recording, demonstrating that replay does not need the synthetic response. The placeholder key is not stored in the cassette.

## Synthetic cassette convention

The committed fixtures in `llm_extract`, `agent_loop` and `secrets` are **synthetic**, not captured live responses. Each fixture directory has a README saying that bodies, IDs and token counts were invented, naming the exchanges and describing regeneration. Their request keys were generated by executing the program with a scripted outer HTTP response under recording mode, so they match the real adapter's serialization. A changed request fails replay and requires deliberate regeneration and review.

A hand-written provider body must wrap the answer as the API does: Anthropic's structured output needs an object at the schema's root, so `Llm.anthropic` asks for `{"value": T}` and decodes the `value` member. The model text `{"value":4}` answers an `Int`; a bare `4` fails `InvalidOutput` with the clause `expected an object with a "value" field`. `Llm.scripted` is the other way round: it takes the JSON of `T` itself (`"4"`), with no wrapper.

All twelve examples execute in run or test mode; these three replay committed fixtures, which is not live-provider validation.

### Multi-turn synthetic cassettes

`Http.scripted` answers every request with its first matching entry, and an agent's turns are all
`POST /v1/messages`, so it cannot return a tool turn and then an answer. To make a multi-turn
cassette, write an outer handler that answers in order:

```sakura
import std/http.{Http}
import std/request.{Method, Request}
import std/response.{HttpError, Response}
import std/url.{Url}

/// Answers each request with the next body, in order. For regenerating a cassette only.
fn in_order(bodies: List<String>) -> Handler<Http> {
  handler Http {
    var next = 0
    fn send(req) {
      let body = Option.unwrap_or(bodies[next], "no more synthetic turns")
      next = next + 1
      Response.status(200, body)
    }
    fn stream(req, body) { fail HttpError { status: None, reason: "in_order does not stream" } }
    fn read_chunk(b, max) { fail HttpError { status: None, reason: "in_order does not stream" } }
  }
}

test "in_order answers each request once, in order" {
  with in_order(["first", "second"]) {
    let req = Request.of(Method.Post, Url.from("https://api.anthropic.com/v1/messages"))
    expect_eq(Response.bytes(Http.send(req), 100), String.to_bytes("first"))
    expect_eq(Response.bytes(Http.send(req), 100), String.to_bytes("second"))
  }
}
```

Put it outermost in a `regenerate` test, `with Budget.unlimited(), in_order([...]), Http.recording(Path.of("turns.jsonl")), Llm.anthropic(...)`,
with the provider bodies the turns should return, and run that test once with
`sakura test --record --filter regenerate`. Each miss is forwarded to `in_order` and appended;
no network is used. In ordinary runs every request hits the cassette and `in_order` is never
reached. **Delete a cassette before regenerating it**: `in_order` sees only the misses, so
against an existing cassette its bodies would answer the wrong turns.

The same recipe records a cassette of your own service with no network: make the outer
handler route each request to the app in-process (`Router.handle(app(), req)` over
`Sql.memory()`), record once under `--record --filter`, then delete the throwaway test and keep
the cassette. Today `--record` still needs a `net` entry in the manifest (see below), even when
nothing leaves the process.

## Streaming responses

`Http.recording` also implements `Http.stream` (design §17.88): a replayed exchange delivers its recorded body to the callback. Under `--record` the handler reads the whole streamed body from the outer `Http` before replaying it to the callback, so recording does not stream through. It records at most 16 MiB (16,777,216 bytes) of a response body, streamed or sent: past that, `Http.stream` or `Http.send` fails with `HttpError` reading `response body over 16 MiB: sakura test --record stores at most 16,777,216 bytes of a response body`, and nothing is appended to the cassette.

`Http.read_chunk` returns at most the requested number of bytes and an empty buffer at EOF. Consume the body inside the callback; it is closed when that scope exits:

```sakura
import std/http.{Http, Matcher}
import std/response.{Response}
import std/request.{Method, Request}
import std/url.{Url}

test "stream reads bounded chunks" {
  with Http.scripted([(Matcher.Any, Response.status(200, "hello"))]) {
    Http.stream(Request.of(Method.Get, Url.from("https://example.com/")), fn(i) {
      expect_eq(Http.read_chunk(i.body, 3), String.to_bytes("hel"))
      expect_eq(Http.read_chunk(i.body, 3), String.to_bytes("lo"))
      expect_eq(Bytes.len(Http.read_chunk(i.body, 3)), 0)
    })
  }
}
```
