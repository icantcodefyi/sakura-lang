<Callout type="warn" title="Format draft">
  This format is the current design. It will be versioned once the checker exists, and fields may be added before then.
</Callout>

Every problem the compiler finds is reported as a JSON object. The format is the same from the command line, the [MCP server](/docs/agents/mcp), and editor integrations.

```bash
vow check --format json
```

The output is a JSON array of diagnostics. Human-readable output (the default) is rendered from the same objects.

## A complete example

```json
{
  "code": "E0402",
  "severity": "error",
  "message": "effect `Net` is performed but not declared in the signature of `signup`",
  "span": { "file": "src/users.vow", "start": { "line": 9, "col": 3 }, "end": { "line": 9, "col": 41 } },
  "expected": "! {Db, Clock, Random, Fail<SignupError>}",
  "found": "! {Db, Clock, Random, Net, Fail<SignupError>}",
  "fixes": [
    {
      "title": "Declare `Net` in the signature of `signup`",
      "safety": "changes-signature",
      "edits": [{ "file": "src/users.vow", "line": 5, "col": 67, "insert": ", Net" }]
    },
    {
      "title": "Remove the call to `Http.post`",
      "safety": "changes-behaviour",
      "edits": [{ "file": "src/users.vow", "start": { "line": 9, "col": 3 }, "end": { "line": 9, "col": 41 }, "replace": "" }]
    }
  ],
  "docs": "/docs/tour/effects.md#undeclared-effects"
}
```

The source this refers to is shown in [Effects: Undeclared effects](/docs/tour/effects#undeclared-effects).

## Fields

| Field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `code` | string | yes | Stable identifier, such as `E0402`. Never reused for a different problem. |
| `severity` | string | yes | `error`, `warning`, `info`, or `hole`. |
| `message` | string | yes | One sentence, in plain English, naming the symbols involved in backticks. |
| `span` | object | yes | Where the problem is: `file`, `start`, and `end`. |
| `expected` | string | no | What the compiler needed: a type, an effect row, or a refinement. |
| `found` | string | no | What it got instead, in the same notation as `expected`. |
| `fixes` | array | yes | Zero or more fixes, best first. May be empty. |
| `docs` | string | yes | Markdown URL of the docs section that explains the rule. |
| `related` | array | no | Other spans involved, each with a `span` and a `message`, such as the declaration a call refers to. |
| `hole` | object | no | Present when `severity` is `hole`. See [Typed holes](/docs/agents/typed-holes). |

### Spans

Lines and columns are 1-based. Columns count Unicode scalar values, not bytes. `start` is inclusive and `end` is exclusive, so a span covers the characters from `start` up to but not including `end`.

### Fixes

| Field | Meaning |
| --- | --- |
| `title` | Short imperative description, suitable for a menu or a commit message. |
| `safety` | `safe`, `changes-behaviour`, or `changes-signature`. |
| `edits` | Text edits to apply, all in one step. |

Each edit is either an insertion (`file`, `line`, `col`, `insert`) or a replacement (`file`, `start`, `end`, `replace`). An empty `replace` deletes the range. All positions in one fix refer to the file before any of its edits are applied.

## Severity

| Severity | Blocks `vow check` | Blocks `vow build` | Meaning |
| --- | --- | --- | --- |
| `error` | yes | yes | The program is wrong. |
| `warning` | no | no | The program is valid but probably not what was meant, such as an unused declared effect. |
| `info` | no | no | Context, such as which contracts were proven. |
| `hole` | no | yes | A `todo()` that still needs filling. Tests can run; release builds cannot. |

## Fix safety levels

The `safety` field tells an agent whether it can apply a fix on its own.

| Level | Meaning | Agent policy |
| --- | --- | --- |
| `safe` | Machine-applicable with no semantic change: formatting, adding an import, removing an unused binding. | Apply automatically. |
| `changes-behaviour` | Changes what the code does, but not its signature. | Apply only if it matches the task. |
| `changes-signature` | Changes a contract: parameter or return types, the effect row, `requires`/`ensures`, refinements, `pub` visibility, or capability grants in `vow.toml`. | Never apply silently. Always flag for human review. |

`changes-signature` is the most important level. The signature is the contract that humans review, so any fix that alters it must reach a human, even when it is obviously correct.

## Code namespaces

| Range | Area |
| --- | --- |
| `E00xx` | Syntax and parsing |
| `E01xx` | Names, modules, imports, visibility |
| `E02xx` | Types and pattern matching (including exhaustiveness) |
| `E03xx` | Refinements and contracts |
| `E04xx` | Effects and handlers |
| `E05xx` | Capabilities, taint, and secrets |
| `E06xx` | Packages and `vow.toml` |
| `Wxxxx` | Warnings, numbered in parallel with the error ranges |
| `H0001` | Typed hole |

Codes are stable across releases. `vow explain E0402`, or the `explain` MCP tool, prints the full explanation.

## Example: refinement violation

```vow title="src/config.vow"
type Port = Int where 1..=65535

let default_port: Port = 70000
```

```json
{
  "code": "E0301",
  "severity": "error",
  "message": "value `70000` does not satisfy the refinement of `Port` (`Int where 1..=65535`)",
  "span": { "file": "src/config.vow", "start": { "line": 3, "col": 26 }, "end": { "line": 3, "col": 31 } },
  "expected": "Port",
  "found": "Int (70000)",
  "related": [
    { "span": { "file": "src/config.vow", "start": { "line": 1, "col": 1 }, "end": { "line": 1, "col": 32 } }, "message": "`Port` is defined here" }
  ],
  "fixes": [],
  "docs": "/docs/tour/contracts.md#where-refinements-are-checked"
}
```

No fix is offered, because the compiler cannot know which port was intended.

## Example: unproven precondition

```json
{
  "code": "E0310",
  "severity": "error",
  "message": "cannot show that `requires b != 0` of `divide` holds for this call",
  "span": { "file": "src/stats.vow", "start": { "line": 4, "col": 3 }, "end": { "line": 4, "col": 29 } },
  "expected": "count != 0",
  "found": "count: Int (unconstrained)",
  "fixes": [
    {
      "title": "Return early when `count == 0`",
      "safety": "changes-behaviour",
      "edits": [{ "file": "src/stats.vow", "line": 4, "col": 3, "insert": "if count == 0 { return 0 }\n  " }]
    },
    {
      "title": "Add `requires count != 0` to `average`",
      "safety": "changes-signature",
      "edits": [{ "file": "src/stats.vow", "line": 2, "col": 1, "insert": "  requires count != 0\n" }]
    }
  ],
  "docs": "/docs/tour/contracts.md#preconditions-requires"
}
```

## Example: capability violation

A dependency update starts using the network, but `vow.toml` grants it nothing:

```json
{
  "code": "E0501",
  "severity": "error",
  "message": "dependency `markdown` 2.2.0 requires effect `Net` in `markdown.render`, which is not granted in vow.toml",
  "span": { "file": "vow.toml", "start": { "line": 2, "col": 1 }, "end": { "line": 2, "col": 31 } },
  "expected": "! {}",
  "found": "! {Net}",
  "fixes": [
    {
      "title": "Grant `Net` to `markdown`",
      "safety": "changes-signature",
      "edits": [{ "file": "vow.toml", "line": 2, "col": 29, "insert": ", grants = [\"Net\"]" }]
    },
    {
      "title": "Pin `markdown` to 2.1.x",
      "safety": "changes-behaviour",
      "edits": [{ "file": "vow.toml", "start": { "line": 2, "col": 25 }, "end": { "line": 2, "col": 28 }, "replace": "=2.1" }]
    }
  ],
  "docs": "/docs/tour/capabilities.md#granting-capabilities-to-dependencies"
}
```

## Example: secret leak

```json
{
  "code": "E0520",
  "severity": "error",
  "message": "`Secret<String>` has no `Show` instance and cannot be interpolated into a string",
  "span": { "file": "src/payments.vow", "start": { "line": 12, "col": 27 }, "end": { "line": 12, "col": 32 } },
  "expected": "a type with `Show`",
  "found": "Secret<String>",
  "fixes": [
    {
      "title": "Remove `{key}` from the log message",
      "safety": "changes-behaviour",
      "edits": [{ "file": "src/payments.vow", "start": { "line": 12, "col": 26 }, "end": { "line": 12, "col": 33 }, "replace": "" }]
    }
  ],
  "docs": "/docs/tour/capabilities.md#secrets"
}
```
