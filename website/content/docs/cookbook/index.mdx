Finish only when no holes remain, independent tests pass, the requested target
builds, and contracts/tests/permissions have not been weakened. Repeat the frozen
baseline check after the final edits. Report missing prerequisites and failing
checks explicitly; do not claim a skipped test passed.

These ten projects teach supported Sakura APIs on the JavaScript backend. Each
project is exercised offline by `cargo test -p sakura_cli --test examples`;
HTTP and LLM exchanges are synthetic committed cassettes, with no network or API keys.
Use Node 26 for execution, including its built-in SQLite implementation.

The initial API baseline is compiler revision
[5cae349516c21714d90d36e87f1cfd6debe980c6](https://github.com/icantcodefyi/sakuralang/commit/5cae349516c21714d90d36e87f1cfd6debe980c6).
CI reruns these projects against the compiler in the same checkout. Build that
checkout's CLI and run `sakura --version` and `sakura prompt` before adapting a recipe.
Sakura Lang is pre-1.0: read STABILITY.md before depending on an API. An installed
skill's frontmatter records its compiler version and build revision. These teaching examples are separate from the agent
evaluation tasks.

The source of each page is its example's `recipe.md`, `sakura.toml`,
`src/main.sak` and fixture files. Run `cargo run -p agent_docs` from `compiler/`
to regenerate the cookbook and skill reference. Edit those sources, not the rendered pages.

## Audit and verify

`sakura audit --json` inventories trust boundaries; it is not certification.
`sakura verify --json` requires the pinned solver and reports each obligation.
Exit 0 can include `unknown` or `unsupported`; inspect statuses and
`path_feasible`, including `W7002` for vacuity. A proof is conditional on its
recorded assumptions and target profile, not a whole-program guarantee.

- [Decode JSON into a refined record](/docs/cookbook/json_refined) — Decode an order once and let its field refinements reject invalid external data.
- [Read a file from a CLI](/docs/cookbook/cli_files) — Decode command-line flags into a record and count a selected file's bytes.
- [Retry HTTP with an offline cassette](/docs/cookbook/http_retry) — Retry a safe GET after a rate limit, with a finite attempt count and virtual time in tests.
- [Query SQLite with bound parameters](/docs/cookbook/sqlite_query) — Keep SQL text literal and interpolate values as parameters, then decode typed rows.
- [Test a router endpoint directly](/docs/cookbook/router_endpoint) — Call the router as a function to test dispatch, request validation and response handling.
- [Exercise an LLM tool with a script](/docs/cookbook/scripted_tool) — Drive a tool call and final answer with scripted model output, then replay the same provider exchange.
- [Bound an agent loop and its budget](/docs/cookbook/budgeted_agent) — Set both a turn limit and a spending limit, and test rejection before an unaffordable call.
- [Update list indices with List.set](/docs/cookbook/indexed_update) — Reassign the new list returned by `List.set` while preserving earlier versions.
- [Build a URL with Url.parse and SearchParams](/docs/cookbook/url_build) — Parse a base URL, set its path and query parameters, and resolve links against it.
- [Upload a file as multipart form data](/docs/cookbook/form_upload) — Build a `multipart/form-data` body with `Form`, send it, and parse it back within limits.
- [Verify a signed webhook with HMAC](/docs/cookbook/sign_webhook) — Check that a webhook delivery carries a valid HMAC-SHA-256 signature before acting on it.
