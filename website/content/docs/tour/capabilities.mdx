  The security model below is designed, not implemented. Grant syntax in `vow.toml` may change.
</Callout>

Most supply-chain attacks and injection bugs rely on code being able to do more than it should: a dependency that reads environment variables, a helper that opens a socket, a string from a request that reaches a SQL query. Vow's design makes each of these a compile error unless it is stated explicitly.

## Effects are capabilities

A function can only perform the effects in its row. A function without `Net` cannot reach the network, however deep the call stack goes, and there is no reflection or global state to get around it.

So the effect row is also a permission list. `fn render(md: String) -> Html` is pure: it cannot read files, phone home, or look at your environment, and the compiler guarantees it.

## The root holds every capability

Authority starts at `main`. Its row lists the root capabilities the program uses, and the runtime provides real handlers for exactly those:

```vow title="src/main.vow"
import app/routes.{routes}

fn main() ! {Net, Env, Fs, Log, Clock, Random, Async} {
  let url = Env.secret("DATABASE_URL")
  with Db.postgres(url) {
    Http.serve(8080, routes())
  }
}
```

There is no way for library code to create `Net` or `Fs` on its own. It can only receive them from a caller whose row already has them.

## Granting capabilities to dependencies

Dependencies get no capabilities unless `vow.toml` grants them:

```toml title="vow.toml"
[dependencies]
markdown = { version = "2.1" }                   # pure: no effects granted
s3 = { version = "0.4", grants = ["Net", "Env"] }
```

If a dependency's public API requires an effect that has not been granted, `vow check` refuses to build. This is checked against the dependency's signatures, so an update that quietly adds `Net` to `markdown` fails the build until someone changes the grant.

```json
{
  "code": "E0501",
  "severity": "error",
  "message": "dependency `markdown` 2.2.0 requires effect `Net` in `markdown.render`, which is not granted in vow.toml",
  "span": { "file": "vow.toml", "start": { "line": 2, "col": 1 }, "end": { "line": 2, "col": 31 } },
  "expected": "! {}",
  "found": "! {Net}",
  "fixes": [
    {
      "title": "Grant `Net` to `markdown`",
      "safety": "changes-signature",
      "edits": [{ "file": "vow.toml", "line": 2, "col": 29, "insert": ", grants = [\"Net\"]" }]
    },
    {
      "title": "Pin `markdown` to 2.1.x",
      "safety": "changes-behaviour",
      "edits": [{ "file": "vow.toml", "start": { "line": 2, "col": 25 }, "end": { "line": 2, "col": 28 }, "replace": "=2.1" }]
    }
  ],
  "docs": "/docs/tour/capabilities.md#granting-capabilities-to-dependencies"
}
```

Granting a capability is treated as a signature change, so it is always flagged for human review.

## Narrowing capabilities

Some handlers restrict an effect instead of removing it. `Net.only` passes network calls through only to listed hosts:

```vow
fn charge(card: CardToken, amount: Cents) -> Receipt ! {Net, Env, Fail<PaymentError>} {
  with Net.only(["api.stripe.com"]) {
    Stripe.charge(card, amount)
  }
}
```

Inside the block, a call to any other host fails with `Fail<NetDenied>`. Similar handlers are planned for files and environment variables: `Fs.only(["./uploads"])`, `Env.only(["STRIPE_KEY"])`.

## Untrusted data

Data from the outside world arrives as `Untrusted<T>`:

- HTTP request parameters, headers, and bodies,
- environment variables read with `Env.get`,
- file contents,
- free text from an `Llm` call.

Sinks that interpret strings, such as `Sql.raw`, `Shell.run`, and `Html.raw`, accept only trusted values. Passing untrusted data to them is a compile error.

```vow title="src/search.vow"
fn search(req: Request) -> Response ! {Db} {
  let q = req.param("q")       // Untrusted<String>
  let pattern = "%{q}%"        // still Untrusted<String>: taint propagates through interpolation
  let rows = Db.query(Sql.raw("select * from posts where title like '{pattern}'"))
  Response.json(200, rows)
}
```

```json
{
  "code": "E0510",
  "severity": "error",
  "message": "`Untrusted<String>` flows into `Sql.raw`, which requires a trusted value",
  "span": { "file": "src/search.vow", "start": { "line": 4, "col": 23 }, "end": { "line": 4, "col": 82 } },
  "expected": "String",
  "found": "Untrusted<String>",
  "fixes": [
    {
      "title": "Use a `sql\"...\"` literal so `pattern` becomes a bound parameter",
      "safety": "changes-behaviour",
      "edits": [{ "file": "src/search.vow", "start": { "line": 4, "col": 23 }, "end": { "line": 4, "col": 82 }, "replace": "sql\"select * from posts where title like {pattern}\"" }]
    }
  ],
  "docs": "/docs/tour/capabilities.md#untrusted-data"
}
```

The fix is the idiomatic version. Tagged literals are safe with untrusted interpolations because they never splice text: `sql"..."` turns each interpolation into a bound parameter, and `html"..."` escapes it.

```vow
let rows = Db.query(sql"select * from posts where title like {pattern}")
let page = html"<h1>Results for {q}</h1>"
```

### Getting a trusted value

There are two ways to turn `Untrusted<T>` into a trusted value.

**Validate it** against a refinement. This is the normal path:

```vow
let email = req.param("email").validate(Email)   // Email ! {Fail<Invalid>}
```

**Trust it explicitly**, with a reason. This is the escape hatch:

```vow
let tag = req.header("X-Internal-Tag").trust_because("set by our own load balancer, stripped from client requests")
```

`trust_because` is easy to grep for and appears in review tooling, so every escape hatch is visible and has a stated reason.

## Secrets

`Env.secret` returns a `Secret<T>`:

```vow
let key = Env.secret("STRIPE_KEY")   // Secret<String> ! {Env}
```

`Secret<T>` has no `Show`, `Json`, or `Log` instances. It cannot be interpolated into a string, printed, logged, or serialized. It can be passed to APIs that accept a `Secret`:

```vow
fn stripe_request(key: Secret<String>, body: Json) -> Response ! {Net} {
  Http.post("https://api.stripe.com/v1/charges", body, auth: Http.bearer(key))
}
```

Trying to log it is a compile error:

```vow
Log.info("using key {key}")   // E0520: `Secret<String>` cannot be interpolated
```

The secret value exists only inside handlers that need it, such as the HTTP client building the `Authorization` header.

## What the compiler checks

- A function performs only the effects in its row, so the row is its full set of permissions.
- Dependencies use only granted effects. Grants are checked against every public signature, on every update.
- Handlers that install real IO require the matching capability in the enclosing row.
- `Untrusted<T>` never reaches a raw sink without `validate` or `trust_because`.
- `Secret<T>` is never shown, logged, or serialized.
- Codes for these checks are in the `E05xx` range. See [Diagnostics](/docs/agents/diagnostics).
