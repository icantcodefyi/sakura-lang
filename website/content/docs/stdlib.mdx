The standard library ("std") is the set of modules that ship with Sakura: collections, text,
JSON, files, HTTP, SQL, model calls, crypto and more. Use this page to look up what a module
offers and what each function takes and returns.

## A quick example

Common types such as `List` and `String` need no import. Other modules are imported by
path, such as `std/url` here:

```sakura test
import std/url.{Url}

fn distinct_words(text: String) -> List<String> {
  List.unique(List.sort(String.split(text, " ")))
}

fn host_of(link: String) -> Option<String> {
  match Url.parse(link) {
    Ok(u) => u.host,
    Err(_) => None,
  }
}

test "distinct words, sorted" {
  expect_eq(distinct_words("to be or not to be"), ["be", "not", "or", "to"])
}

test "a URL's host" {
  expect_eq(host_of("https://Example.com/docs"), Some("example.com"))
  expect_eq(host_of("not a url"), None)
}
```

For examples of whole programs, see the [cookbook](/docs/cookbook), the
[capabilities tour](/docs/tour/capabilities), the [contracts tour](/docs/tour/contracts) and the
[cassette guide](/docs/agents/cassettes). To search std offline, by name or by a type such as
`fn(List<A>) -> Int`, use [`sakura doc`](/docs/agents/doc).

## How to read a signature

The [signatures](#signatures) below are declarations, not programs you can run.

- `fn len(b: Bytes) -> Int` takes a `Bytes` value and returns an `Int`.
- `! {Http, Fail<HttpError>}` after the result lists the function's *effects*: what it may do
  besides compute a value, such as send HTTP requests or fail with a typed error
  (`Fail<HttpError>`). Your function has to declare these effects too, or handle them.
- `requires …` is a precondition. Calling the function with arguments that break it is a bug
  in the caller, reported at run time as the defect `D020`.
- `type` declares a data type, `error` an error type, and `effect` an effect with its
  operations. A `Handler<E>` is a value that implements the effect `E`; install one with
  `with`, as in `with Http.scripted(…) { … }`, for example to answer HTTP requests from a
  script in a test.
- `// @resource` marks a value, such as an open file, that must stay inside the callback that
  gave it to you; returning it is `V6003`. `// @external` marks a function the runtime
  implements.

## Current limits

**Not available yet**

- `Sql.postgres` is not implemented and has no release assigned. SQLite and the in-memory SQL
  database cover the current examples.
- Static verification (`sakura verify`) covers a restricted subset of programs; see the
  [roadmap](/docs/roadmap).

**Available**

- Offline test helpers (`Http.recording`, `Llm.replay`, `Llm.recording`, `Test.fixtures`),
  `Untrusted.validate`, `Html.from` and streaming HTTP (`Http.stream`, `Http.read_chunk`,
  `Body`, `Incoming`) are implemented.

**Numbers**

- An `Int` on the JavaScript backend is exact within ±(2^53−1); on WebAssembly it is a signed
  64-bit integer. Both are CLI targets; native is experimental.

**Where to find things**

- `Task.par_map` lives in `std/task`, not `List`.
- `Env.host()` takes no scope argument; use `Env.only` to narrow what a program may read.
- For dense integer IDs, prefer `List`, as the DeltaBlue benchmark does; use `Map` for sparse
  keys. Updating a collection returns a new value, so assign the result back. The
  [source index](https://github.com/icantcodefyi/sakuralang/blob/main/compiler/std/INDEX.md) has
  complexity and behavior notes.

**Untrusted input in templates**

- An `Untrusted<String>` (text from outside the program) placed in `sql"…"` becomes a bound
  parameter, in `html"…"` escaped text, and in `url"…"` percent-encoded through `UrlPart.from`.

The [web API differences](#web-api-differences) at the end of this page say how std's versions
of the browser, Node and Bun APIs differ from the originals.

## Prelude

These names are in scope in every module without an import:

| Kind | Names |
|---|---|
| Compiler-known types | `Unit Bool Int Float String Bytes Never List Map Set Range Handler Secret Untrusted` |
| Std types | `Option Result Duration Instant Uuid Json Level Violation` (`Violation` is what `validate` returns) |
| Constructors | `Some None Ok Err` (other variants are used qualified: `Level.Warn`, `Json.String(s)`) |
| Effects | `Fail` (compiler-known) `Console Clock Random Env Log Task Test` |
| Functions | `show expect expect_eq expect_fail expect_fails_with expect_defect expect_output expect_snapshot` (the `expect` functions need `Test`, which only `test`/`property` bodies have; elsewhere they are `V3001`) |
| Tags | `sql html url` (`shell` is reserved by the prelude; no `std/shell` exists yet) |

Not in the prelude, import them: `import std/retry.{Policy, retry}`, `import std/task.{Timeout, timeout}`,
`import std/gen` (`gen.int(0, 9)`), `import std/graph.{Graph, NodeId}`, and every other std module.

Home modules: `T.f(…)` and `x.f(…)` with `x: T` call `f` in the module that
declares `T`; for compiler-known types it is `std/<lowercase name>` (`List` → `std/list`). An
effect's home module is the one declaring it, and `Eff.f(…)` calls a home-module function
when `f` is not an operation (`Console.captured()`, `Clock.fixed(t)`, `Random.seeded(1)`).

```sakura fragment
fn of(table: Permissions) -> Grants
type WorkerReason = GrantExceeded | Limit | Defect(String) | Codec
error WorkerError(reason: WorkerReason)
type Received<T> = Message(T) | Finished | Failed(WorkerError)
opaque type Port<S, R> = { id: Int, sends: Bool, tx: Option<Sender<String>>, rx: Option<Receiver<String>> }    // @resource
type WorkerHandle<I, O> = Port<I, O>
type Inbox<I> = Port<Never, I>
type Outbox<O> = Port<O, Never>
opaque type Topic<T> = { name: String }
effect Worker {
  fn start<I, O, R, e>(entry: fn(Inbox<I>, Outbox<O>) -> Unit ! e, named: List<fn(Inbox<I>, Outbox<O>) -> Unit ! e>, grants: Grants, body: fn(WorkerHandle<I, O>) -> R ! e) -> Result<R, WorkerError> ! e
  fn post<S, R>(p: Port<S, R>, text: String) -> Result<Unit, SendError>
  fn take<S, R>(p: Port<S, R>) -> Received<String>
  fn publish_text(name: String, text: String) -> Result<Unit, SendError>
  fn subscribe_text<R, e>(name: String, capacity: Int, body: fn(Inbox<String>) -> R ! e) -> R ! e
  fn close<S, R>(p: Port<S, R>) -> Unit
}
fn spawn<I: Schema, O: Schema, R, e>(entry: fn(Inbox<I>, Outbox<O>) -> Unit ! {Worker | e}, grants: Grants, body: fn(WorkerHandle<I, O>) -> R ! {Worker | e}) -> Result<R, WorkerError> ! {Worker | e}
fn send<S: Schema, R>(p: Port<S, R>, m: S) -> Result<Unit, SendError> ! {Worker}
fn recv<S, R: Schema>(p: Port<S, R>) -> Received<R> ! {Worker}
fn topic<T: Schema>(name: String) -> Topic<T> requires String.len(name) <= 256
fn publish<T: Schema>(t: Topic<T>, m: T) -> Result<Unit, SendError> ! {Worker}
fn subscribe<T: Schema, R, e>(t: Topic<T>, capacity: Int, body: fn(Inbox<T>) -> R ! {Worker | e}) -> R ! {Worker | e} requires capacity > 0
fn inline() -> Handler<Worker, {Task}>
fn host() -> Handler<Worker>
```

## Web API differences

std offers the web platform's APIs, the ones browsers, Node and Bun provide, as typed Sakura
values. This section maps each one to its Sakura name and says where the behavior differs.
The full design is
[RFC 0002](https://github.com/icantcodefyi/sakuralang/blob/main/docs/rfcs/0002-web-platform-apis.md).

### Bytes and text

- `Uint8Array` is `Bytes`, which is immutable, so an in-place write is
  `Bytes.from_list(List.set(...))`.
- `TextEncoder.encodeInto` has no counterpart, because there is no caller-owned buffer.
- `btoa` takes bytes, so text goes through `String.to_bytes` first.
- `Encoding.encode` writes UTF-8 and UTF-16 only, since Windows-1252 cannot encode every string.

### URLs

- `URL` is `Url.parse` and `Url.resolve`, which give a `UrlParts` value, and `URLSearchParams`
  is `SearchParams`.
- The setters are `with_*` functions that return a new value, so there is no live
  `url.searchParams`: read `Url.search` and write `Url.with_search`.
- A host that needs IDNA (non-ASCII, or an `xn--` label) is `UrlError(Idna)` until punycode
  lands.
- The password is a `Secret`, which `to_string` leaves out.
- `Url` stays the prefix check that `url"…"` and `Request.url` use.

### Crypto

- `crypto.subtle` is `std/crypto`, synchronous and pure.
- `importKey` takes the material as `Secret<Bytes>`, and a `CryptoKey` is never `Show`.
- `verify` is reserved as a bare name, so call it `crypto.verify(key, tag, data)` or
  `key.verify(tag, data)`.
- A key without the operation's usage is the defect `D020`, not an error value.
- A key's `type` is `crypto.kind(key)`, a `KeyKind` (`SecretKey`, `PublicKey` or
  `PrivateKey`), because `type` is a Sakura keyword.
- Web Crypto's `generateKey` returns a key or a `CryptoKeyPair` depending on the algorithm.
  Sakura's `generate_key` makes only HMAC and AES-GCM keys, and `generate_key_pair` returns a
  `KeyPair { public, private }`, because a function has one result type.
- An AES-GCM nonce (Web Crypto's `iv`) is exactly 12 bytes, from `Random.bytes(12)`. Any other
  length is `CryptoError(Nonce(n))` on every backend, because 96 bits is the bound the lowest
  host supports and a longer nonce is a different construction with a weaker bound.
- An RSA-OAEP seed must be unpredictable as well as fresh (`Random.bytes(n)`, never a
  counter): a seed an attacker can guess lets them confirm a guessed plaintext by sealing it
  themselves.
- ECDSA is P-256 with SHA-256 only (JOSE `ES256`) and takes no `hash` parameter, because the
  curve fixes the hash.
- ECDSA signatures are `r || s` (64 bytes) but are not the same bytes on every backend
  (OpenSSL's random nonce through `node:crypto` on JS and WASM, RFC 6979 on native, and neither
  is promised), so compare them with `verify`, never by value.
- On `--target wasm` every primitive runs in the Node host through `hosted` imports, which a
  WASI command does not have.
- The [`sign_webhook`](/docs/cookbook/sign_webhook) recipe verifies an HMAC signature.

### Headers, blobs and forms

- `Headers` is a validated value over the `List<(String, String)>` that `Request.headers` and
  `Response.headers` keep: `Headers.of` to read, `to_list` to write back.
- `get` on `set-cookie` is `None`, since cookies are never joined; read `get_set_cookie`.
- Credentials stay in `Request.secret_headers`.
- `Blob` and `File` are the values `Blob` and `FileData`, which name no file on disk.
- `Blob.text` is strict UTF-8 (`Utf8Error`) where the web substitutes U+FFFD.
- `Blob.stream()` is `Blob.source(b, chunk)`.
- `FormData` is `Form`, and `Response.formData()` is `Form.parse_multipart` with a required
  `FormLimits`.

### URL patterns

- `URLPattern` is `UrlPattern`, a subset with no regular expressions, so a pattern matches
  alike on every target: whole-segment `:name` groups, `*` for one segment and `**` for any
  number, on a path or behind a literal scheme, host and port.
- The standard's `*` is `.*` and crosses `/`. Sakura's `*` is exactly one segment and `**` is
  any number, because `**` already covers a tree and a route author does not expect
  `/files/*` to match one.
- The standard is exact about a trailing slash. `UrlPattern` ignores empty segments on both
  sides, so `/users/7/` matches `/users/:id`, because that is the contract `Router` routes
  already had.
- Regexp groups, `{…}` groups, modifiers and a group inside a segment are
  `PatternError(Unsupported)`.
- A pattern has at most 4,096 bytes and 64 groups.
- `exec` returns the groups only, in pattern order, unnamed ones as `"0"`, `"1"`, ….
- `Router` routes are these patterns, and a route pattern `UrlPattern.compile` rejects is the
  defect `D020`.

### Streams

- `ReadableStream` is `std/stream`'s `Source<T, e>`, a value whose `pull` returns `Done` or
  `Next(item, rest)`, and `WritableStream` is `Sink<T, e>`.
- The web's readers, writers, controllers and locks have no counterpart. A web stream is
  locked so that consumers aliasing it do not interleave; a Sakura source is a value that one
  instance pulls on one thread.
- A pure source (`Source.from_list`, `Blob.source`) reads the same items each time it is
  pulled.
- `Http.body_source`, `Fs.file_source` and `Fs.file_sink` are views over a body or file, valid
  only inside the callback that opened it (`V6003`).
- A transform is a function from source to source. `TextDecoderStream` and
  `TextEncoderStream` are `Encoding.decode_source` and `encode_source`.
- `to_list` and `lines` take a required bound and fail `StreamError` past it.
- `ReadableStream.tee` is `Source.tee` and `CountQueuingStrategy` is `Source.buffer`, both over
  `std/channel`.
- `ByteLengthQueuingStrategy` has no counterpart: `Source.chunks(src, size)` before `buffer`
  bounds bytes, because `chunks` re-cuts bytes to exactly `size` and `buffer` counts items.
- BYOB readers and byte controllers are not provided, because Sakura has no caller-owned
  buffer to read into.

### WebSockets

- `WebSocket` is the effect of `std/websocket`.
- The `Bun.serve` upgrade is `WebSocket.accept(req, options, body)` inside a `Serve` handler,
  on the client's `Socket` and operations, after the pure `WebSocket.handshake(req)`.
  `server.upgrade`'s `data` and the `open`/`message`/`close`/`drain` callbacks are not
  provided, because the body is a function of the socket and every event is a value `receive`
  returns.
- Bun's topics are `subscribe`, `unsubscribe` and `publish(topic, message, except)`,
  instance-local, and a publisher never waits: a subscriber whose send buffer holds
  `max_message` bytes misses the message.
- `origins` refuses every browser origin it does not name, unlike Bun, because a browser sends
  the victim's cookies with the upgrade.
- `idleTimeout`, `sendPings` and `perMessageDeflate` are not mirrored: an idle policy is
  `Task.timeout` around `receive`, and no extension is negotiated.
- `SAKURA_MAX_SOCKETS` (1,024) bounds the open sockets of both roles.
- `onopen`, `onmessage`, `onclose` and `addEventListener` are not provided. `open` is
  `WebSocket.connect`'s callback, and `message` and `close` are the values `receive` returns
  (`Data(Text(s))`, `Data(Binary(b))`, `Closed(CloseInfo)`, the close returned again by every
  later receive), because Sakura has no event listeners and a returned value is matched
  exhaustively. `Data` wraps the `Message` because one module cannot declare `Text` and
  `Binary` twice.
- `bufferedAmount` and `readyState` are not provided, since `send` waits while the buffer is
  full and `receive` reports the close.
- `permessage-deflate` and every other extension are refused in the handshake, so
  `WebSocket.extensions` has no counterpart, because an inflated frame would be a
  decompression surface outside the `max_message` bound.
- Credentials have no `secret_headers` field yet: `Options.headers` are plain strings, so a
  `Secret` reaches one only through `Secret.expose`, because a secret-carrying handshake import
  waits for the owner's sign-off.
- `max_message` (16 MiB by default) bounds both directions and the receive queue. The
  connection stops reading while 64 received messages, or more than `max_message` bytes of
  them, wait, and a ping is answered only while the send buffer needs no drain, so a ping
  flood cannot grow it.
- `net` covers `ws` (port 80) and `wss` (443). The opening handshake follows no redirect.
- Native executables run `WebSocket` from `v1.0.0-beta.6` (experimental with the target).
- The [`websocket_server`](/docs/cookbook/websocket_server) and
  [`websocket_client`](/docs/cookbook/websocket_client) recipes show both roles.

### Channels

- `MessageChannel` and `MessagePort` are `std/channel`'s `with_channel(capacity, body)`, whose
  body receives a `Sender` and a `Receiver`. Both are resources, so neither leaves the
  callback.
- `send` waits while `capacity` items are queued, `try_send` fails `Full` instead, and `recv`
  waits while empty and is `None` once closed and drained.
- There is no `onmessage` listener, `postMessage` transfer list or `structuredClone`, because a
  message is a value that `recv` returns and values are copied by assignment.
- `with` is a keyword, so the RFC's `Channel.with` is `with_channel`.
- `BroadcastChannel` is `Worker.topic` (experimental, below).
- `CountQueuingStrategy` is `Source.buffer(src, capacity, body)` and `ReadableStream.tee` is
  `Source.tee(src, max_lag, body)`, both over a channel with a producer task.
- The source a `buffer`, `tee` or `decompress_source` body receives reads `Done` once that
  callback returns, so keep it inside the callback. `V6003` does not catch this, because the
  source holds no resource type.
- A byte bound is `chunks` before `buffer`, so `ByteLengthQueuingStrategy` has no counterpart.
- A program in which every task waits ends with the defect `D090`.

### Workers (experimental)

Workers are **experimental** and outside the 1.0 contract.

- `Worker` (`new Worker`) is `std/worker`'s `Worker.spawn(entry, grants, body)`, where `entry`
  is a function declared `@worker` that runs as a second instance of the program with its own
  heap and root handlers.
- `postMessage` is `send`, and `onmessage` and `ErrorEvent` are the `Message` and `Failed`
  values `recv` returns. Messages cross through the `Schema` codec, so there is no
  `structuredClone` or transfer list, and a `Secret` cannot cross.
- `ShadowRealm` is a worker with `Grants.none()`. Grants are a subset of the parent's
  `[permissions]`, checked at `spawn`.
- `BroadcastChannel` is `Worker.topic` with `publish` and `subscribe`.
- `terminate()` is the end of `spawn`'s callback. `Worker.close(p)` ends one direction, as
  `MessagePort.close` does.
- At most 16 workers are live per instance.
- `Worker.inline()` runs a worker as a fiber for tests on every target. Live workers and topics
  run on every target: as threads on JavaScript and on WebAssembly under Node, and as OS
  threads on native.
- A stopped native worker keeps its thread until its next wait. A pure loop can keep `spawn`
  from returning, and granted `Fs` writes can continue until that wait.
- Worker grant paths must match the manifest's exact strings: `"./data"` and `"data"` do not
  match.
- A native worker whose entry leaves to the runtime an effect native does not serve (`Llm`,
  `Serve`, `WebSocket`, and `Http` through `v1.0.0-beta.3`) is refused at its start, and its
  parent reads `Failed(WorkerError(Defect("exit 75")))`.

### Compression

- `CompressionStream` and `DecompressionStream` are `std/compress`'s `compress_source` and
  `decompress_source`, callback-shaped like the other views; `compress` and `decompress` work
  on whole `Bytes`.
- The formats are the web's three: `Gzip`, `Deflate` and `DeflateRaw`.
- Decompression takes a required `max_out` and fails `CompressionError(OutputLimit)` past it,
  so a small input cannot expand without bound. Malformed input is `Malformed(offset)` and a
  cut-off stream `Truncated`.
- Trailing data and a second gzip member are refused, as in `DecompressionStream`.
- Compressed bytes may differ between backends, but each backend decompresses the others'
  output.
- The [`stream_lines`](/docs/cookbook/stream_lines) recipe reads a gzipped log.
