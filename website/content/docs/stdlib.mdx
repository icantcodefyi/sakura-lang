## Finding an API

Use the compiler MCP `symbol_query` and `docs_query` tools, or read [`compiler/std/`](https://github.com/icantcodefyi/sakura-lang/tree/master/compiler/std). `sakura doc --search` is planned M3 completion work. Each effect and type has a home module: `List.map` is `std/list.map`; `Request.json` lives in `std/request`, and `Response.status` in `std/response`.

`Option`, `Result`, `List`, `Map`, `Set`, `String`, `Int`, `Float`, `Bytes`, `Json`, `Secret`, `Untrusted`, and compiler-known `Trust` are available through the prelude. `Console`, `Clock`, `Random`, `Env`, `Log`, `Task`, and `Test` are prelude effects. Import other effects and types explicitly, for example `import std/sql.{Sql, SqlError}`.

## Data and contracts

The implemented surface includes persistent collections, UTF-8 strings, bytes, JSON schemas/codecs, durations/instants, UUIDs, paths, URLs, decimal values and graphs. Refined values are checked when introduced or decoded. `Json.decode` takes its target from the surrounding annotation: `let user: User = Json.decode(text)?`.

JS `Int` arithmetic is checked against its representable range: beyond ±(2^53−1) is `D003`, and beyond i64 is `D001`. Parsing an out-of-range integer returns `None`. Full-range i64 execution is planned for WASM; it is not today's JS representation.

## Effects and handlers

These constructors exist today. Production adapters run under Node; fake handlers make tests independent of external services.

| Effect | Host or production | Test or attenuation |
| --- | --- | --- |
| `Console` | `Console.host()` | `Console.captured()` |
| `Clock` | `Clock.host()` | `Clock.fixed(instant)`, `Clock.virtual()` |
| `Random` | `Random.host()` | `Random.seeded(seed)` |
| `Env` | `Env.host()` | `Env.of(map)`, `Env.only(keys)` |
| `Log` | `Log.stderr()`, `Log.json()` | `Log.captured()` |
| `Fs` | `Fs.host()` | `Fs.rooted(dir)`, `Fs.memory(files)` |
| `Http` | `Http.host()` | `Http.scoped(hosts)`, `Http.scripted(script)` |
| `Serve` | `Serve.host()` | `Serve.scripted(requests)` |
| `Sql` | `Sql.sqlite(path)` | `Sql.memory()` |
| `Cli` | `Cli.host()` | `Cli.of(args)` |
| `Budget` | `Budget.limits(limits)` | `Budget.unlimited()` |
| `Llm` | `Llm.anthropic(key, model)` | `Llm.scripted(responses)` |
| `Task` | `Task.host()` | `Task.deterministic(seed)` |

`sakura run` checks startup grants and supplies `[permissions]` through `SAKURA_PERMISSIONS` to the host handlers. `Http.scoped` accepts a list of allowed host strings; there is no `NetScope` API. `Fs.with_file` supplies a callback with a `File`; reads/writes go through `Fs.read_chunk` and `Fs.write_chunk`, with finalization on exit. Complete scoped escape checks remain an M3 gate.

## SQL and HTML

`sql"select id from users where email = {email}"` builds an opaque `Query<R>` and binds interpolated values as SQL parameters. The compiler inserts `SqlValue.from` when an interpolation is not already a `SqlValue`. Strings, refined strings and `Untrusted<String>` become text parameters; they are not SQL identifiers or syntax.

`Sql.memory()` is backed by an in-memory SQLite database. `Sql.sqlite(path)` uses the installed `Fs` authority. `Sql.transaction` rolls back on failure, defect or cancellation. `Sql.postgres` is not implemented.

`html"…"` escapes text interpolations. Use `Html.concat` to compose `Html` values; nested `Html` interpolation conversion remains completion work. Opaque `Query<R>` and `Html` constructors and fields cannot be accessed from other modules (`V1006`).

## HTTP, routing and CLI

`Http.send` returns HTTP responses, including error statuses, and fails when no response arrives. `Http.bearer` stores credentials in `Request.secret_headers` for the host sink. `Request` and `Response` are separate home modules.

The following are signature sketches (not declarations to paste into a program):

```sakura
fn Router.new<e>() -> Router<e>
fn Router.post<e>(r: Router<e>, pattern: String, h: fn(Request) -> Response ! e) -> Router<e>
fn Router.handle<e>(r: Router<e>, req: Request) -> Response ! e
fn Serve.listen<e>(router: Router<e>, addr: Address) -> Never ! {Serve, Fail<ServeError> | e}
```

`Serve.serve(handle, addr)` is the effect operation; `Serve.listen` is the router convenience function. `Cli.parse` decodes arguments into the annotated record type. `sakura new api <name>` scaffolds a checked API project. For full programs, use the checked [JSON API](https://github.com/icantcodefyi/sakura-lang/tree/master/compiler/examples/json_api) and [word-count](https://github.com/icantcodefyi/sakura-lang/tree/master/compiler/examples/word_count) examples.

## Tools, LLMs and agents

`Tool.of(f)` takes a named function marked `@tool("description")`, derives an argument record/schema and lowers through `Tool.from`. Arguments decode with refinements checked; the function runs under the caller's handlers, and typed failures become `ToolError`. The model supplies arguments, never authority.

The current type shapes preserve tool effects:

```sakura
// Signature sketches; import the named types from their home modules.
type Agent<T, e> = {
  request: Request<T>,
  tools: List<Tool<e>>,
  max_steps: Int,
  stop: fn(Partial<T>) -> Bool,
}
fn Agent.run<T: Schema, e>(a: Agent<T, e>) -> T ! {Budget, Llm, Fail<LlmError | ToolError> | e}
```

`Tool<e>` and `Router<e>` also take row parameters. `Request<T>` in `std/llm` has `system`, `user`, `model`, `max_tokens`, and `temperature`; tools belong to the agent configuration, not the request. `LlmError` includes `BudgetExceeded`.

Bodiless `@llm` functions generate an `Llm.generate` request and validate the output schema/refinements. `Llm.anthropic` implements generation, tool turns and SSE streaming: `on_partial` is called once per text delta. Local mock tests exercise the adapter; this documentation does not claim a live API test. `Llm.scripted` provides offline responses. Replay cassettes and HTTP recording are still planned.

The [LLM extraction](https://github.com/icantcodefyi/sakura-lang/tree/master/compiler/examples/llm_extract) example runs offline tests. The [agent loop](https://github.com/icantcodefyi/sakura-lang/tree/master/compiler/examples/agent_loop) example currently has check-only harness coverage.

## Tests, generators and trust

Tests/properties, snapshots, `expect_fail`, `expect_defect`, `std/gen`, retry policies, task timeouts and `Task.par_map` are implemented. Typed failures may escape a test body and count as a failed test. Other effects need an installed handler (`V3020`). `par_map` lives in `std/task`, not `List`.

`Untrusted.of`, `len`, `check(u, clause, pred)` and `trust(u, @trust("reason"))` exist. Refined-target `Untrusted.validate` remains completion work. `Secret.expose` also requires an inline trust reason. `Trust` is a compiler-known prelude type; storing or otherwise using `@trust` outside a trusted sink argument is `V6001`.

## Remaining work

M3 still needs its [exit gates](/docs/roadmap), including escape/validation rules, audit/doc/manifest tooling, generated contract tests and recording/replay coverage. WASM and static verification are M4; native execution and Perceus reuse are M5. Package tooling and PostgreSQL placement remain owner decisions. No browser host library, durable workflow engine or package registry is shipped.
