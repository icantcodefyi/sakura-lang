## Current scope and limitations

- `Http.recording`, `Llm.replay`, `Llm.recording`, `Test.fixtures`, `Untrusted.validate` and `Html.from` are implemented, as is streaming HTTP (`Http.stream`, `Http.read_chunk`, `Body`, `Incoming`, design §17.88).
- `Sql.postgres` is not implemented and has no release assigned. SQLite and memory SQL cover the current examples.
- `Untrusted<String>` interpolated into `sql"…"` is a bound parameter and into `html"…"` escaped text (design §17.101); in `url"…"` it is percent-encoded through `UrlPart.from`.
- `Task.par_map` lives in `std/task`, not `List`. `Env.host()` takes no scope argument; use `Env.only` for attenuation.
- JS `Int` arithmetic has a safe-integer range of ±(2^53−1); WASM uses signed i64. Both are CLI targets; native is experimental.
- Web byte and text APIs (RFC 0002): `Uint8Array` is `Bytes`, immutable, so an in-place write is `Bytes.from_list(List.set(...))`; `TextEncoder.encodeInto` has no counterpart because there is no caller-owned buffer; `btoa` takes bytes, so text goes through `String.to_bytes` first; `Encoding.encode` writes UTF-8 and UTF-16 only, since Windows-1252 cannot encode every string.
- Web URL APIs (RFC 0002): `URL` is `Url.parse` and `Url.resolve` giving a `UrlParts` value, and `URLSearchParams` is `SearchParams`; the setters are `with_*` functions returning a new value, so there is no live `url.searchParams` (read `Url.search`, write `Url.with_search`); a host that needs IDNA (non-ASCII, or an `xn--` label) is `UrlError(Idna)` until punycode lands; the password is a `Secret` that `to_string` leaves out. `Url` stays the prefix check `url"…"` and `Request.url` use.
- Web Crypto (RFC 0002): `crypto.subtle` is `std/crypto`, synchronous and pure; `importKey` takes the material as `Secret<Bytes>` and a `CryptoKey` is never `Show`. `verify` is reserved as a bare name, so call it `crypto.verify(key, tag, data)` or `key.verify(tag, data)`. A key without the operation's usage is `D020`, not an error value. On `--target wasm` they run in the Node host.
- Web headers, blobs and forms (RFC 0002): `Headers` is a validated value over the `List<(String, String)>` that `Request.headers` and `Response.headers` keep (`Headers.of` to read, `to_list` to write back); `get` on `set-cookie` is `None`, since cookies are never joined, so read `get_set_cookie`; credentials stay in `Request.secret_headers`. `Blob` and `File` are the values `Blob` and `FileData`, which name no file on disk; `Blob.text` is strict UTF-8 (`Utf8Error`) where the web substitutes U+FFFD; `Blob.stream()` waits for `std/stream`. `FormData` is `Form`, and `Response.formData()` is `Form.parse_multipart` with a required `FormLimits`.
- Static verification is implemented for a restricted fragment; see the [roadmap](/docs/roadmap).
- Prefer `List` for dense integer IDs, as in DeltaBlue; use `Map` for sparse keys. Collection updates return new values: assign the result back. See the source index for complexity and behavior notes.

## Prelude

In scope in every module without an import (design §9, with the additions marked +):

| Kind | Names |
|---|---|
| Compiler-known types | `Unit Bool Int Float String Bytes Never List Map Set Range Handler Secret Untrusted` |
| Std types | `Option Result` · + `Duration Instant Uuid Json Level` (prelude effects mention them; §15.1 and §15.4 use `Instant.format_iso`, `Level.Warn`, `Json.String` unimported) |
| Constructors | `Some None Ok Err` (other variants are used qualified: `Level.Warn`, `Json.String(s)`) |
| Effects | `Fail` (compiler-known) `Console Clock Random Env Log Task` · + `Test` |
| Functions | `show` · + `expect expect_eq expect_fail expect_fails_with expect_defect expect_output expect_snapshot` (they need `Test`, which only `test`/`property` bodies have; elsewhere they are `V3001`) |
| Tags | `sql html url` (`shell` is reserved by the prelude; no `std/shell` exists yet) |

Not in the prelude, import them: `import std/retry.{Policy, retry}`, `import std/task.{Timeout, timeout}`,
`import std/gen` (`gen.int(0, 9)`), `import std/graph.{Graph, NodeId}`, and every other std module.

Home modules (design §4.9): `T.f(…)` and `x.f(…)` with `x: T` call `f` in the module that
declares `T`; for compiler-known types it is `std/<lowercase name>` (`List` → `std/list`). An
effect's home module is the one declaring it, and `Eff.f(…)` calls a home-module function
when `f` is not an operation (`Console.captured()`, `Clock.fixed(t)`, `Random.seeded(1)`).
