**Today there is no compatibility promise.** The latest release is the beta `v1.0.0-beta.4`;
the earlier preview, `0.1.0`, stays on the default channels. Behaviour may change before 1.0.0.

<Callout type="warn" title="The beta">
  `v1.0.0-beta.4` is a beta of 1.0 and **not for production**. It may have bugs, and it may
  change before 1.0.0, including the contracts below. Every breaking change between the beta
  and 1.0.0 is listed in the [changelog](/changelog) with a migration. It is published as a GitHub
  prerelease, on npm under the `beta` tag and as the Homebrew formula `sakuralang-beta` ([Install](/docs/install#the-beta)); `npm i -g sakuralang` and
  `brew install sakuralang` stay on `0.1.0`.
</Callout>

[Draft RFC 0001](https://github.com/icantcodefyi/sakuralang/blob/main/docs/rfcs/0001-stability-guarantees.md)
proposes the guarantees below. Its final comment period does not gate the beta: the guarantees
bind from the release at which the owner accepts the RFC, and in full from `v1.0.0`. Until then
the policy in [STABILITY.md](https://github.com/icantcodefyi/sakuralang/blob/main/STABILITY.md)
applies, and that file's inventory is the authoritative list.

## Levels

- **Stable**: covered by the RFC's compatibility rules from the version named. From
  `1.0.0-beta.1`, machine contracts (diagnostic codes, `--json` records, exit codes, the WASM
  ABI) are meant to change only additively, but during the beta they may still change, each
  with a migration in the changelog; source and standard-library changes come with a listed
  migration. From `1.0.0`, source and standard-library compatibility hold within a major
  version.
- **Experimental**: may change or disappear in any release. Opt-in and labelled.
- **Internal**: an implementation detail with no promise, even when you can see it.

## By area

| Area | Proposed level | From |
| --- | --- | --- |
| [CLI](/docs/cli) commands, documented flags, exit codes and environment variables | stable | 1.0.0-beta.1 |
| `build --emit`, `--layout`, `--dump`; hidden switches | experimental or internal | — |
| [`sakura.toml`](/docs/manifest): `[package]`, `[permissions]`, `[verify]`; the `V8005` and `V8006` refusals | stable | 1.0.0-beta.1 |
| [Diagnostic codes](/docs/errors): a code is never reused or renumbered | stable | 1.0.0-beta.1 |
| [`--json` records](/docs/agents/diagnostics#record-kinds): fields are only added within a major | stable | 1.0.0-beta.1 |
| [Standard library](/docs/stdlib) public signatures | stable | 1.0.0-beta.1 with a listed migration; 1.0.0 within a major |
| [`std/worker`](/docs/tour/concurrency#workers-experimental) and the `@worker` attribute; live workers on every target | experimental | — |
| WASM runtime ABI | stable | 1.0.0-beta.1 |
| JS backend ABI, generated code, LIR and Core, the compiler's Rust crates, cache files | internal | — |
| [Language server](/docs/editors) standard protocol features | stable | 1.0.0-beta.1 |
| The `sakura/holeContext` LSP extension | experimental | — |
| [MCP](/docs/agents/mcp) stdio tools and the snapshot and patch protocol | stable | 1.0.0-beta.1 |
| `--target native` and the native runtime (in the macOS arm64, Linux x64 and Linux arm64 release binaries from v1.0.0-beta.4) | experimental | — |

Human-readable output, help text, diagnostic wording and generated code bytes are never
contracts. A diagnostic's code, fields and fixes are.

## Changes made before the guarantees

These decisions (design §17.239–§17.243, §17.253) are built, ahead of the first version that
honours the guarantees, so they are not breaking changes under the RFC:

- **Lexical rules.** An `Int` literal is in `[0, 2^63 − 1]`; write the minimum as `Int.min`.
  A digit separator `_` goes only between two digits.
- **A source file that is not UTF-8** becomes a diagnostic,
  [`V0015 source_not_utf8`](/docs/errors/V0015), instead of a usage error.
- **`[permissions] process` is reserved.** `process = []` is accepted and grants nothing,
  the same as leaving the key out. A non-empty list, which 0.1.0 accepted and which also
  granted nothing, is [`V8006`](/docs/errors/V8006).

## After 1.0

Packages arrive additively in 1.x; until then `[dependencies]` is refused. Native code
generation stays experimental. The current plan, pending the owner's confirmation, is that it
gates no release and ships as an experimental flag once its test matrix is green.

Deprecations after 1.0 get warnings and a migration for at least two minor releases and six
months before removal.
