## Install

With [Node 26](https://nodejs.org) installed (`sakura run` and `sakura test` execute the generated JavaScript with `node`):

```bash
npm install --global sakuralang
sakura --version
```

```text
sakura 0.1.0-alpha.1
```

Homebrew (`brew tap icantcodefyi/sakuralang && brew install sakuralang`) and a checksum-verifying installer are also available; see [Install](/docs/install). The standard library is embedded in the binary, so `sakura` works from any directory.

## Install from source

To use the features listed in [changes since alpha.1](/docs/changes), build from source. You need [rustup](https://rustup.rs) and Node 26. The repository pins its Rust toolchain in `compiler/rust-toolchain.toml`, so rustup fetches the right version on first build.

```bash
git clone https://github.com/icantcodefyi/sakuralang
cd sakuralang/compiler
cargo install --locked --path crates/sakura_cli
sakura --version
```

To try it without installing, run `cargo run -p sakura_cli -- <command>` inside `compiler/`.

## Run an example

`compiler/examples/` holds the design's twelve example programs and eight [cookbook](/docs/cookbook) recipes as projects. Every one runs or tests in CI; none is check-only. From a checkout:

```bash
sakura run compiler/examples/counter
```

```text
1. milk
2. eggs
1. bread
```

`counter` is a user-defined effect whose handler keeps state. `sakura test compiler/examples/typed_errors` runs a program that recovers from typed failures with `try`/`catch`. The [examples README](https://github.com/icantcodefyi/sakuralang/blob/main/compiler/examples/README.md) records each project's mode.

## Create a project

Run `sakura new cli hello` to scaffold a project (`lib`, `agent`, and `api` templates also exist), or write the two files below by hand. A project is a `sakura.toml` manifest and a `src/` directory, and one file is one module.

The scaffold also writes `AGENTS.md`, short instructions for coding agents (check the compiler version, read `sakura prompt`, run `check`, `fmt --check` and `test`, never widen a contract to pass), and a `CLAUDE.md` that imports it with `@AGENTS.md`. `sakura init` writes them only when they are absent and never overwrites a file.

```toml title="hello/sakura.toml"
[package]
name = "hello"
version = "0.1.0"
edition = "2026"

[permissions]
```

`[permissions]` is the ceiling on what the program may do (design §6). This program only prints, so it is empty. `sakura run` enforces startup grants and passes the table as `SAKURA_PERMISSIONS` for host-handler enforcement. Missing required root authority exits with 75.

A program is one package over std. `[dependencies]` is reserved for packages, which arrive in a later minor release; a manifest that declares it, even empty, is refused with [`V8005`](/docs/errors/V8005) before anything runs. Any other table or key the manifest does not define, a value of the wrong type or malformed TOML is [`V8006`](/docs/errors/V8006), reported by `sakura check` at the place in `sakura.toml`. See [sakura.toml](/docs/manifest) for every key.

```sakura title="hello/src/main.sak"
/// Build a greeting for a person.
fn greet(name: String) -> String { "Hello, {name}" }

pub fn main() -> Unit ! {Console} { Console.print(greet("world")) }

test "greets by name" { expect_eq(greet("Ada"), "Hello, Ada") }

property "always starts with Hello"(name: String) {
  expect(String.starts_with(greet(name), "Hello, "))
}
```

`greet` has no `!`, so it is pure. `main` declares `Console`, the only effect the program performs. This is the canonical layout: `sakura fmt` keeps a short body on its signature's line.

## Check, test and run

Run these from `hello/`. With no path, each command uses `src/`.

```bash
sakura check
```

```text
no problems
```

`sakura check` parses, resolves names, checks types and effects, and checks that every `match` is exhaustive. It generates no code, and it accepts typed holes.

```bash
sakura test
```

```text
test greets by name ... ok
test always starts with Hello ... ok

2 passed, 0 failed, 0 skipped (seed 0)
```

`sakura test` runs every `test` and `property` block under deterministic handlers (a fixed clock, a seeded random source, captured console output) with the network denied. `--seed 7` changes the property inputs, `--filter greets` runs matching tests only, and `--json` writes one record per test.

```bash
sakura run
```

```text
Hello, world
```

`sakura run` checks the program, compiles it to JavaScript under `target/sakura/js/`, and runs `main` with `node`. Arguments after `--` go to the program. The exit code is the program's: `0` for success, `1` when `main` fails with an uncaught typed error, `70` for a defect such as integer overflow, with one JSON `defect` record on stderr.

`sakura fmt` rewrites files in the one canonical format; `sakura fmt --check` changes nothing and exits `1` if a file is not formatted.

## Check it, as an agent would

Suppose `greet` starts printing without declaring it:

```sakura expect=V3001 title="hello/src/main.sak"
/// Build a greeting for a person.
fn greet(name: String) -> String {
  Console.print("greeting {name}")
  "Hello, {name}"
}

pub fn main() -> Unit ! {Console} { Console.print(greet("world")) }
```

```text
error[V3001]: function `greet` performs `Console`, which its signature does not allow (allowed: `{}`)
  ┌─ src/main.sak:2:4
  │
2 │ fn greet(name: String) -> String {
  │    ^^^^^
3 │   Console.print("greeting {name}")
  │   -------------------------------- `Console.print` performs `Console` here
  │
  = expected: {}
  =    found: {Console}
  = help: Add `Console` to the signature
  = help: Handle the effect locally with `with`
  = see `sakura explain V3001`

1 error
```

`sakura check --json` writes the same error as JSON Lines, one record per line, followed by a `summary` record. The `diagnostic` record, pretty-printed with hashes shortened:

```json
{
  "schema_version": "1.0",
  "kind": "diagnostic",
  "id": "d:e8f9a0e1d729d3d1",
  "code": "V3001",
  "severity": "error",
  "phase": "effect",
  "message": "function `greet` performs `Console`, which its signature does not allow (allowed: `{}`)",
  "snapshot": "sha256:9470da24…",
  "symbol_id": null,
  "spans": [
    { "uri": "file:///…/hello/src/main.sak", "content_hash": "sha256:f1ee9f10…",
      "start_byte": 38, "end_byte": 43, "role": "primary" },
    { "uri": "file:///…/hello/src/main.sak", "content_hash": "sha256:f1ee9f10…",
      "start_byte": 72, "end_byte": 104, "role": "cause",
      "label": "`Console.print` performs `Console` here" }
  ],
  "related_ids": [],
  "expected": { "render": "{}", "row": { "labels": [], "tail": null } },
  "actual": { "render": "{Console}", "row": { "labels": [{ "effect": "std::Console", "args": [] }], "tail": null } },
  "obligation": null,
  "counterexample": null,
  "explanation_uri": "sakura://explain/V3001",
  "fixes": [
    { "id": "f:e8f9a0e1d729d3d1.0", "title": "Add `Console` to the signature",
      "applicability": "suggested", "impact": "interface_change",
      "edits": [{ "span": { "uri": "file:///…/hello/src/main.sak", "content_hash": "sha256:f1ee9f10…",
                            "start_byte": 67, "end_byte": 67, "role": "primary" },
                  "replacement": " ! {Console}" }] },
    { "id": "f:e8f9a0e1d729d3d1.1", "title": "Handle the effect locally with `with`",
      "applicability": "incomplete", "impact": "local",
      "edits": [/* wraps the body in `with ?handler { … }` */] }
  ]
}
```

Spans are zero-based, half-open UTF-8 byte offsets, and an edit applies only while `content_hash` still matches. The first fix changes the function's interface, so it is `suggested`, never `machine_applicable`: an agent must not widen a signature silently. `sakura explain V3001` prints the rationale with a wrong and a fixed program. See [Diagnostics](/docs/agents/diagnostics) for the format.

A typed hole is how an agent asks the compiler what fits:

```sakura holes
fn unfinished(x: Int) -> Int { ?result }
```

```text
hole ?result: expected Int, effects {}; locals [x: Int]; candidates [x, Int.abs(?i), Int.clamp(?i, ?lo, ?hi), …]
```

`sakura check` accepts holes; `sakura build` and `sakura run` reject them with `V2050`. See [Typed holes](/docs/agents/typed-holes).

## Commands

| Command | Today |
| --- | --- |
| `sakura check [--json] [paths]` | Parse, resolve, type and effect check, exhaustiveness. Holes allowed |
| `sakura build [paths]` | Check, then generate JavaScript. Holes rejected (`V2050`) |
| `sakura run [path] [-- args]` | Build and run `main` with `node` |
| `sakura test [--json] [--seed N] [--filter text] [--update-snapshots]` | Run tests and properties with deterministic handlers |
| `sakura fmt [--check] [paths]` | Canonical format. There are no options |
| `sakura explain V3001` | Rationale, causes and repairs for a diagnostic code |
| `sakura prompt` | Print the language guide for agents ([llms.txt](https://github.com/icantcodefyi/sakuralang/blob/main/docs/llms.txt)) |
| `sakura verify [--json] [paths]` | Prove contracts and arithmetic with Z3 ([Verify contracts](/docs/agents/verify)) |

`build`, `run` and `test` take `--target wasm` to use the WebAssembly backend. Also available: `sakura new`, `sakura init`, `sakura setup`, `sakura fix`, `sakura audit`, `sakura doc`, `sakura check --frozen-specs all [--since rev]`, `sakura lsp`, and `sakura mcp serve`. The [CLI reference](/docs/cli) lists every command, flag and exit code, and [sakura.toml](/docs/manifest) the manifest. There are no package commands: packages arrive after 1.0. See [changes on main](/docs/changes) for differences from the published preview.
