## 1. What Sakura Lang is

Sakura Lang is an **agent-first programming language**: the programming language built for
agents. It works like this:

- A function's signature states three things: what the function may do (its **effects**), how it
  may fail (its **typed errors**) and what it guarantees (its **contracts**).
- The compiler holds the body to that signature.
- Humans review signatures, which are short.
- Agents write the bodies. They get structured, machine-readable feedback: diagnostics with
  fixes that state their impact, and typed holes.

```sakura
fn withdraw(acct: Account, amount: Cents)
  -> Account
  ! {Ledger, Fail<Overdrawn | Frozen>}
  requires positive: amount > 0
  ensures result.balance == acct.balance - amount
{ ... }
```

**Language core** (design §0–§10):

- **Execution model.** Strict and eagerly evaluated. Expressions, braces, `fn`, `let`/`var`,
  nominal records and variants, exhaustive `match`.
- **Types.** Rank-1 generics with Hindley–Milner inference. Every top-level function has an
  explicit signature.
- **Effect rows** such as `! {Db, Clock, Fail<E>}`:
  - They are inferred inside bodies and declared as upper bounds on signatures.
  - Effects are requirements; **handlers** (`with h { ... }`) are authority.
  - All std effects, including Console, Fs, Http, Clock and Random, are ordinary `effect`
    declarations.
  - Handlers are tail-resumptive: no `resume`, no multi-shot.
- **Typed errors.** `Fail<E>` over unions of nominal `error` tags, used with `fail`, `try`,
  `catch` and `?`.
- **Defects.** Contract violations, overflow and division by zero are not errors. They terminate
  the task with a `D0xx` record.
- **Contracts.** `requires`, `ensures` and refinement types (`type Cents = Int where it >= 0`)
  are always checked at runtime. `sakura verify` proves obligations with Z3 and removes the
  checks it proves.
- **Capabilities.** `main` only gets what `[permissions]` in `sakura.toml` grants. Libraries can
  narrow authority, never widen it. `Secret` and `Untrusted` are taint types.
- **Value semantics.** No aliasing, no reference cells, closures capture by value. JS uses the
  host's garbage collector. WASM and native use reference counting, with Perceus-style reuse
  planned (M5b).
- **Fast by default** (§17.103). Every feature needs a zero- or near-zero-cost fast path:
  - an effect with a known handler compiles to a direct call (the "direct twin");
  - rows and refinements are erased after checking.

**Tooling.** One `sakura` binary does everything:

- `new`, `check`, `fmt`, `build`, `run`, `test`, `verify`, `audit`, `doc`, `fix`;
- `setup` (installs the agent skill and MCP entry);
- `mcp serve` (tools: `check`, `apply_patch`, `hole_context`, `test` and more);
- `lsp`.

`--json` emits versioned records. The machine-readable contracts:

- diagnostic codes: [`compiler/diagnostics/codes.txt`](../../compiler/diagnostics/codes.txt);
- JSON fields: [`compiler/contracts/json.txt`](../../compiler/contracts/json.txt);
- the WASM/native runtime ABI: `compiler/runtime/rt/ABI.md`.

## 2. How the compiler works

The pipeline (design §13, §14) is a Cargo workspace in `compiler/crates/`:

```
source .sak
  → sakura_syntax      lexer, event parser, Rowan CST (error-tolerant)
  → sakura_hir         desugar, name resolution, module graph
  → sakura_types       HM + bidirectional checking, effect rows, holes, exhaustiveness
  → sakura_core        Core IR, match compilation, contract lowering, opt::owned (ownership facts)
  ├→ sakura_codegen_js     Core → JS (CPS trampoline + direct-style fast path) + runtime/js
  ├→ sakura_core_snapshot → sakura_lir (low-level IR)
  │     ├→ sakura_codegen_wasm    wasm-encoder; runtime in linear memory (runtime/rt, no_std Rust)
  │     └→ sakura_codegen_native  Cranelift (experimental, behind the `native` feature)
  │          + sakura_host_native, sakura_native_driver
  sakura_analysis      the facade every frontend uses (incremental, std analysis disk cache)
  sakura_diagnostics   Diagnostic/Span/Fix, codes registry, JSON + human renderers
  sakura_fmt           formatter     sakura_verify   SMT obligations (Z3 worker)
  sakura_cli / sakura_lsp / sakura_mcp   thin frontends
```

- **std** is written in Sakura itself: 44 modules in `compiler/std/*.sak`, among them `list`,
  `map`, `json`, `http`, `serve`, `sql`, `llm`, `task` and `test`. The host handlers live in
  `runtime/js` and `runtime/rt`.
- **Backends:**
  - **JS** is the default target and runs on Node 26.
  - **WASM** is complete at M4. Its corpus output is identical to JS on stdout, effect traces
    and defect records.
  - **Native** (Cranelift) is experimental. It agrees with JS on 179 of 179 corpus programs, but
    Http, serve and Llm aren't ported yet.
- **Tests:**
  - `compiler/tests/` holds UI fixtures (program plus expected diagnostics), semantics fixtures
    (program plus expected stdout) and formatter fixtures.
  - Parity tests run every program on JS, WASM and native and compare the results.
  - A reference evaluator is used for differential testing, and there are fuzz targets.
  - Snapshots are checked in, and every snapshot diff gets reviewed.

`run-window.sh`, a convenience wrapper over release.md §2 that stops at the first run that wasn't
quiet:

```bash
#!/bin/bash
cd "$(dirname "$0")" || exit 1
mkdir -p bench/target
L=bench/target/window.log
: > "$L"
quiet() { python3 -c "import json,sys;sys.exit(0 if json.load(open('$1'))['meta']['host']['quiet'] is True else 1)"; }
step() {
  echo "=== $(date '+%H:%M:%S') $1" >> "$L"
  shift
  "$@" >> "$L" 2>&1 || { echo "FAILED: $*" >> "$L"; exit 1; }
}
until [ "$(sysctl -n vm.loadavg | awk '{print ($2<2.0)?1:0}')" = 1 ]; do sleep 30; done
step js python3 research/10-evidence/record_load.py --log bench/target/quiet-load-js.jsonl -- \
  bench/bench run --suite js --stable --json bench/target/quiet-js.json
quiet bench/target/quiet-js.json || { echo "ABORT: js not quiet" >> "$L"; exit 3; }
step wasm python3 research/10-evidence/record_load.py --log bench/target/quiet-load-wasm.jsonl -- \
  bench/bench run --suite wasm --stable --json bench/target/quiet-wasm.json
quiet bench/target/quiet-wasm.json || { echo "ABORT: wasm not quiet" >> "$L"; exit 3; }
step native python3 research/10-evidence/record_load.py --log bench/target/quiet-load-native.jsonl -- \
  bench/bench run --suite native --lane matched --stable --json bench/target/quiet-native.json
step compile bench/bench compile --json bench/target/quiet-compile.json
step envelope bench/bench envelope bench/target/quiet-wasm.json bench/target/quiet-native.json \
  --json bench/target/envelope.json --md bench/target/envelope.md
echo "WINDOW_DONE $(date '+%H:%M:%S')" >> "$L"
```
