# Plan: rename Vow to Sakura Lang

Date: 2026-10-18. Owner decision: the language is **Sakura Lang**. Status: approved design; execution is mechanical and is done by one engineer in one PR. Design §17 entry 47 records the decision.

This file is the only place in the repository that keeps the old name on purpose. Nothing in it is an instruction to keep the old name anywhere else.

Scope: names, identifiers, paths and copy. Not in scope: the palette and logo migration (sakura theme, Sakura Seal mark), which is a separate website task; the engineer must not restyle anything here. The only visual change is the wordmark text.

## 1. Naming decisions

| Surface | Decision | Rationale |
|---|---|---|
| Display name | **Sakura Lang**, always both words, in every prose position including possessive (`Sakura Lang's`) and adjective (`a Sakura Lang module`). Never `Sakura` alone for the language. | Owner rule: no short form. `sakura` as a colour or flower word (`sakura palette`) is ordinary vocabulary, not a name, and stays allowed. |
| Where a short label is needed | The Sakura Seal mark alone (favicon, OG tile, status bar). | Owner rule: the logo stands in for a short form. |
| Code identifier | `sakura` | Owner's choice; one lowercase word is what every identifier context needs, and it is the machine form of the name, not an abbreviation. |
| CLI binary | `sakura` (`sakura check`, `sakura test`, `sakura mcp serve`). Cargo package `sakura_cli`, `[[bin]] name = "sakura"`. | The binary is the identifier. |
| Source extension | **`.sakura`** | No-short-form rule rules out `.sk`, `.skr`, `.sak`, `.sl` (`.sl` also collides with S-Lang and RenderMan SL). A web search on 2026-10-18 found no language or tool using `.sakura`; it is unambiguous for editors and Linguist. Four extra characters per file name is the whole cost. |
| Manifest | `sakura.toml` | Same `<identifier>.toml` pattern as today; the manifest is found by exact file name. |
| Lockfile | `sakura.lock` | Pairs with the manifest (design §9). No lockfile is written yet; name only. |
| Crate prefix | `sakura_` (`sakura_syntax`, …, `sakura_cli`, `sakura_eval`) | Rust convention; mechanical from the identifier. |

The letters stop meaning the old name the moment §12.3 says what they mean. |

## 2. Brand voice: promise and seal, not vow

The word *vow* is retired from our own prose entirely, including as ordinary English. After the rename it reads as a leftover, and keeping it would make the final `git grep` check meaningless. The voice keeps the ideas it carried: **promise**, **contract**, **signature**, **seal**. The Sakura Seal is the compiler's seal pressed on a checked signature, so "sealed" is the verb that pairs with the logo.

## 3. Execution checklist (engineer)

Run from the repository root unless a step says otherwise. Every step is deterministic; do not improvise names. Work on a branch, one commit per numbered phase, PR title `refactor: rename Vow to Sakura Lang` (Conventional Commits; the old name is allowed in the PR title and commit messages).

Preconditions: `git status` clean; Rust toolchain from `compiler/rust-toolchain.toml`; Bun 1.4.3; Node available for `cargo test`; `cargo install cargo-insta` (or use the `INSTA_UPDATE=always` fallback in step 3.6).

### 3.1 Path renames

Rename every tracked path whose name contains `vow` with `git mv`, directories first. The complete list of directories:

```
compiler/crates/vow_analysis      -> compiler/crates/sakura_analysis
compiler/crates/vow_cli           -> compiler/crates/sakura_cli
compiler/crates/vow_codegen_js    -> compiler/crates/sakura_codegen_js
compiler/crates/vow_core          -> compiler/crates/sakura_core
compiler/crates/vow_diagnostics   -> compiler/crates/sakura_diagnostics
compiler/crates/vow_fmt           -> compiler/crates/sakura_fmt
compiler/crates/vow_hir           -> compiler/crates/sakura_hir
compiler/crates/vow_lsp           -> compiler/crates/sakura_lsp
compiler/crates/vow_mcp           -> compiler/crates/sakura_mcp
compiler/crates/vow_syntax        -> compiler/crates/sakura_syntax
compiler/crates/vow_types         -> compiler/crates/sakura_types
compiler/tools/vow_eval           -> compiler/tools/sakura_eval
website/lib/vow                   -> website/lib/sakura
```

Then every file: `*.vow` → `*.sakura` (std, examples, tests, fixtures), `vow.toml` → `sakura.toml` (every example), `compiler/runtime/js/vow_runtime.js` → `sakura_runtime.js`, `website/content/docs/why-vow.mdx` → `why-sakura-lang.mdx`, insta snapshot files `*.vow.snap` → `*.sakura.snap` and `vow_syntax__*.snap` → `sakura_syntax__*.snap` (insta derives both from the input file name and the crate name, so the renamed files must match or the tests will write duplicates).

One loop does all of it, file by file (git tracks files, not directories; `mkdir -p` creates the new directories):

```sh
git ls-files | grep -E '(^|/)[^/]*vow[^/]*(/|$)' | while read -r p; do
  q=$(printf '%s' "$p" | sed -E 's#why-vow#why-sakura-lang#g; s#/vow_#/sakura_#g; s#/vow\.toml$#/sakura.toml#; s#\.vow(\.snap)?$#.sakura\1#; s#/vow/#/sakura/#g')
  [ "$p" != "$q" ] && mkdir -p "$(dirname "$q")" && git mv "$p" "$q"
done
find compiler/crates compiler/tools website/lib -type d -empty -delete   # old crate dirs must not survive: `members = ["crates/*"]` would see them
git ls-files | grep -i vow   # expected: docs/plans/rename-sakura-lang.md only
```

Check: `git ls-files | grep -E 'vow' | grep -v docs/plans/rename-sakura-lang.md` prints nothing, and `ls compiler/crates compiler/tools website/lib` shows no `vow` entry. Note the `tests/ui/V####_*` directories stay (code letters are kept).

### 3.2 Content substitutions

Apply the patterns below, in this order, to every tracked text file **except**: `docs/plans/rename-sakura-lang.md` (this file), `website/bun.lock` (untouched, verified in 3.8), `compiler/Cargo.lock` (regenerated in 3.5), binary files per `.gitattributes`. Lines containing the marker `rename:keep` are skipped by every pattern (the marker is used by exactly the lines added in 3.4).

The patterns are word-boundary aware (`\b`) and specific before generic. They run under perl, not sed, because BSD sed on macOS has no `\b`; `perl -pi` edits in place identically on macOS and Linux. One command, after excluding the files above (no tracked file name contains a newline):

```sh
git ls-files \
  | grep -v -E '^(docs/plans/rename-sakura-lang\.md|website/bun\.lock|compiler/Cargo\.lock)$' \
  | grep -v -E '\.(png|jpg|jpeg|gif|ico|webp|woff|woff2|pdf)$' \
  | tr '\n' '\0' | xargs -0 perl -pi -e '
    next if /rename:keep/;
    s#icantcodefyi/vow\b#icantcodefyi/sakura-lang#g;
    s#vowlang\.vercel\.app#sakura-lang.vercel.app#g;
    s#why-vow#why-sakura-lang#g;
    s#vow://#sakura://#g;
    s#\bvow\.toml\b#sakura.toml#g;
    s#\bvow\.lock\b#sakura.lock#g;
    s#\.vow\b#.sakura#g;
    s#__vow_test__#__sakura_test__#g;
    s#_vow_#_sakura_#g;
    s#CARGO_BIN_EXE_vow\b#CARGO_BIN_EXE_sakura#g;
    s#\bVOW_#SAKURA_#g;
    s#\bvow_#sakura_#g;
    s#\bvow-#sakura-#g;
    s#\bVow([A-Z][A-Za-z]*)#Sakura$1#g;
    s#\bvow([A-Z][A-Za-z]*)#sakura$1#g;
    s#\bVow\x27s\b#Sakura Lang\x27s#g;
    s#\bVows\b#Sakura Lang#g;
    s#\bVow\b#Sakura Lang#g;
    s#\bVOW\b#SAKURA#g;
    s#\bvows\b#promises#g;
    s#\bvow\b#sakura#g;
  '
```

(`\x27` is the apostrophe, written that way only because the program is inside single quotes. Under `-p`, `next` still prints the line, unchanged.)

What each rule covers, so the diff can be reviewed by category: repo URL; domain; docs route; URI scheme; manifest and lockfile; extension in paths and prose; test driver file; mid-identifier `_vow_` (one test name, `containers_render_as_vow_syntax`); cargo test env; env vars; crate names, runtime externals (`@external(js, "sakura_runtime", …)`), `sakura_files` helper, planned crate names in research; theme names and the pre-push temp dir; CamelCase types; camelCase website identifiers; prose possessive; prose plural; prose name; the `HELLO, SAKURA!` expected output; English plural; and finally the bare identifier (CLI commands, `"sakura"` string ids, `lang="sakura"`, code fences, `greet("sakura")` and its expected stdout).

Snapshot files (`*.snap`) are included on purpose: their contents hold `"Vow"` literals, `.vow` paths and `vow_runtime.js` imports, and the sed keeps them in sync so step 3.6 produces header-only diffs.

### 3.6 Snapshots

In `compiler/`:

```sh
